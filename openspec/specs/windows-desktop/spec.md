# windows-desktop Specification

## Purpose
使 Image Studio 在用户确认的 Windows 10 x64 目标环境中具有可安装、可持久使用且进程可回收的原生桌面基础，并将构建、界面、设备与模型实测分开记录，避免用其他平台或编译结果代替实际可用性。

## Requirements

### Requirement: Windows 目标构建和支持范围有真实证据

应用 SHALL 在 Windows 10 x64 目标环境完成桌面宿主、诊断与监督程序的本机构建、启动和集成验证，记录 OS build、架构、工具链、依赖锁、WebView2 和设备/驱动身份。只通过核心编译、Mac 交叉检查、CI、Windows 11 或设备小算子的结果 MUST 不被标为目标 Win10 GUI 或完整模型认证。

#### Scenario: Windows 编译通过但尚未运行
- **WHEN** Windows 目标编译通过而 Win10 原生验收尚未执行
- **THEN** 报告仅声明构建通过，GUI、生命周期、安装包与模型各项保持未验证

#### Scenario: 目标机原生验收
- **WHEN** 在 Win10 x64 / RTX 3080 Ti 12 GB / 32 GB RAM / i7-13700K 上完成适用验收
- **THEN** 记录实际系统、驱动、包和证据范围，不外推为其他 Windows 版本或所有 NVIDIA GPU 支持

### Requirement: Windows 目录和受控文件操作可可靠使用

应用 SHALL 在当前用户的本地应用数据位置解析独立 data/cache/logs/work 目录，支持 `--data-dir` 隔离根与按数据根的单实例。登录会话内同一数据根的第二次启动 SHALL 激活已运行实例的主窗口（还原最小化窗口并置于前台）并以成功状态退出，MUST NOT 构造第二个宿主、打开第二套 WebView2 用户数据目录，也 MUST NOT 让用户看到 WebView2 初始化错误形式的启动失败。激活在 5 s 内无法确认时，第二次启动 SHALL 以“已在运行但未响应”或“数据目录正被另一个实例使用”的明确原因提示并按成功状态退出，不得改写数据库或启动另一套模型执行。中文、空格和合法特殊字符 SHALL 原样通过原生路径与进程参数；不可写、无效、受占用或逃逸管理边界的路径 SHALL 明确拒绝并保留已有数据，不回退源码目录。候选和导出 SHALL 保持普通文件、路径归属、内容验证、覆盖确认及失败不损坏旧文件的合同。

#### Scenario: 中文用户名与安装目录
- **WHEN** 用户目录、安装目录或隔离数据根包含中文和空格
- **THEN** 应用能启动、保存并重开会话、运行受管程序及导出 PNG，路径不被解释为命令

#### Scenario: 同根第二实例
- **WHEN** 用户在已有实例运行时再次启动，且两次使用同一数据根（允许路径大小写与短文件名差异）
- **THEN** 第二次启动不打开数据库、不创建 WebView2 用户数据目录，已运行窗口被还原并置于前台，第二个进程以退出码 0 结束
- **AND** 不出现“Image Studio 启动失败”，第二次启动不写 `logs/startup-failure.log`

#### Scenario: 同根实例无响应或位于另一登录会话
- **WHEN** 同一数据根的另一个实例存在，但在 5 s 内未确认激活（无响应，或属于另一个 Windows 登录会话）
- **THEN** 第二次启动显示说明该情况的中文原生提示并以退出码 0 结束，给出“结束该进程后重试”的动作
- **AND** 数据库、作品与模型安装记录不被第二个进程改写，不并发启动第二套模型执行

#### Scenario: 不同数据根的两个实例
- **WHEN** 第二个宿主使用不同的 `--data-dir` 同时启动
- **THEN** 两个实例各自使用属于自己的 WebView2 用户数据目录并按各自数据根工作，不因共享浏览器 profile 或缓存互相中断

#### Scenario: 重解析路径或目标被占用
- **WHEN** 候选/导出路径越界、包含逃逸重解析点或目标无法安全写入
- **THEN** 操作失败且说明恢复动作，旧目标、正式资产与制作记录保持完整

### Requirement: 启动失败可解释且不静默退出

原生窗口、WebView2 运行时或其用户数据目录初始化失败时，应用 SHALL 在数据根的 `logs/` 写入包含底层错误、时间、日志路径与建议动作的启动失败记录，并向用户显示可关闭的原生错误说明，以登记的非零启动失败退出码结束。它 MUST NOT 只以 panic 退出码或进程无提示消失结束，也 MUST NOT 因启动失败改写已有会话、任务、作品或模型安装记录。

#### Scenario: WebView2 缺失或初始化失败
- **WHEN** WebView2 运行时缺失、损坏或无法创建用户数据目录，应用无法显示主界面
- **THEN** 应用写入 `logs/startup-failure.log`，弹出中文错误对话框说明原因与下一步，并以登记退出码 3 结束；不出现只有 101 的静默退出

#### Scenario: 启动失败后再次正常启动
- **WHEN** 一次启动因环境原因失败，随后环境修复
- **THEN** 原有 SQLite 会话/任务/作品与模型安装记录仍可读，再次启动正常工作，失败日志保留供排查

### Requirement: Windows 原生日常操作完整

应用 SHALL 提供可工作的窗口最小化、最大化、关闭、拖拽与原生文件对话框，保存和恢复会话/偏好。中文 IME 组合确认 SHALL 不误触发送。1280×800 与 960×640 逻辑窗口及 100%/150%/200% DPI SHALL 保留导航、输入、发送/停止、模型状态和主要动作，图片和本地资源 SHALL 在 WebView2 中正常显示；未安装模型仍能查看、重开和导出已有作品。发送 SHALL 在有界时间内进入执行或给出可行动失败：停留在 pending 且无 job 超过 60 s 的轮次 MUST 转为 failed 并说明阶段与原因。取消 SHALL 在 15 s 内落定为 `cancelled`；超时允许强制回收进程并标注原因，不得无限停留在"正在取消"。子进程（监督器、worker、安装辅助程序）MUST NOT 弹出控制台窗口：Windows 上创建进程 SHALL 使用 `CREATE_NO_WINDOW`，用户在一次生成或安装期间 MUST NOT 看到新的终端窗口。

#### Scenario: 输入法候选确认
- **WHEN** 用户通过 Windows 中文输入法按 Enter 确认候选文字
- **THEN** 本次按键只确认组合，不发送；组合结束后的显式发送才创建任务

#### Scenario: 缩窗或改变显示缩放
- **WHEN** 用户在规定逻辑尺寸与 DPI 组合使用原生应用
- **THEN** 主要操作可见且可用，拖拽区不吞按钮操作，弹层和图片不遮挡必要控制

#### Scenario: 连续发送不挂起
- **WHEN** 用户连续发送多次（含前一次取消或失败）
- **THEN** 每次发送要么进入执行，要么在 60 s 内以包含阶段与阻塞点的可行动错误结束；不得停留在"正在接收提示词"直到重启应用

#### Scenario: 生成不弹终端
- **WHEN** 用户发起一次生成或一次安装
- **THEN** 期间不出现新的控制台/终端窗口（无新的 conhost/OpenConsole/WindowsTerminal 进程）

#### Scenario: 取消在时限内落定
- **WHEN** 用户在生成中点"停止"
- **THEN** 15 s 内任务变为已取消；若进程未在宽限期退出，则强制回收并标注原因，资产库不出现半成品

### Requirement: Windows 受管理执行可整树回收

诊断、安装探针、生成 worker 及受控后代 SHALL 在受管理生命周期中运行，不经 shell。启动早期失败、取消、超时、宿主/监督被强制终止 SHALL 清理对应进程树；执行租约与占用状态 SHALL 阻止清理完成前重入。合作取消超过 3 秒 SHALL 发起强制回收，以 5 秒为清理截止；不能确认回收时 SHALL 保留清理异常/忙碌，不宣称 GPU 或租约已释放。重启 MUST 不依据历史 PID 盲目终止进程。

#### Scenario: 宿主或监督被强杀
- **WHEN** 真实采样中宿主或监督程序被终止
- **THEN** 对应计算与后代被回收，未提交结果不进入作品；重新启动后记录中断，只有用户显式重试才创建新 Attempt

#### Scenario: worker 派生子进程并挂起
- **WHEN** 故障 worker 产生受控后代后不响应取消
- **THEN** 整个执行树被回收，回收确认前不启动下一任务，不以只结束父 PID 作为完成

#### Scenario: 进程尚未归组时发生启动错误
- **WHEN** 系统无法建立受管理计算或启动中途失败
- **THEN** 不允许未受管理的 worker 开始计算，清理已创建句柄与进程并返回原因

### Requirement: 内部测试安装包可独立安装和启动

应用 SHALL 提供 Windows x64 当前用户级 EXE 内部测试安装包，包含必要宿主/监督/诊断程序、图标、字体、前端和缺失 WebView2 时的离线安装依赖。首次启动 SHALL 不下载模型、准备 Python、修改系统环境或安装 GPU 驱动。程序升级 SHALL 保留用户数据和版本化模型；卸载 SHALL 保留数据、模型、作品和日志，不把内部未签名测试产物宣称为正式签名发布。

#### Scenario: 无开发工具的测试用户安装
- **WHEN** 用户从内部测试包安装，机器没有 Node、Rust、系统 Python 或完整 CUDA Toolkit
- **THEN** 应用可在满足登记系统运行依赖后启动，未安装模型时显示真实状态，不要求开发环境

#### Scenario: 缺失 WebView2 且断网
- **WHEN** 测试环境没有 WebView2、外网被禁止并执行安装包
- **THEN** 使用包内受控离线依赖完成准备；权限或依赖条件不满足时明确说明原因，不假称已安装成功

#### Scenario: 覆盖安装和卸载后重装
- **WHEN** 用户覆盖安装或卸载后重新安装内部测试版本
- **THEN** 既有会话、偏好、模型和正式作品保留，程序从安装目录可重开并导出旧作品

### Requirement: Windows 功能页/模型页投影七个型号与八项能力

Windows 功能页 SHALL 只把已接入且依赖真实的能力显示为可开始；模型页 SHALL 显示七个型号的接入、安装、运行时、设备与可执行状态，以及硬件门槛和许可；设置页 SHALL 显示 v1/v2 运行时与探测结果。

#### Scenario: 功能入口
- **WHEN** 用户浏览功能页
- **THEN** 文生图、图片编辑、去背景、放大等能力按型号真实状态展示，不创建无后端支撑的假任务

#### Scenario: 硬件或安装不满足
- **WHEN** 型号未安装、运行时不就绪或设备低于门槛
- **THEN** 界面显示可操作原因并禁用生成入口，不静默失败、不自动切换到其他型号

### Requirement: 启动前校验 Windows 数据目录路径长度

Windows 桌面 SHALL 在打开 WebView2、创建数据子目录或启动任何安装/下载之前，按**最终**运行时布局（`data/runtimes/rt-<12 hex>` + 最长可被 Python 打开的文件）校验数据目录绝对路径长度，并在 canonicalize 之后再次校验实际路径；超出支持边界时 SHALL 写入 `<数据根>/logs/startup-failure.log`、展示中文可操作提示并以文档化退出码 3 退出，不得进入下载/解压阶段。

边界由最终布局推导：`data + 10 (\runtimes\) + 15 (rt-<12 hex>) + 1 + 130 (最长 Python 可打开相对路径) + 10 (Win32 余量) <= 260`，即数据路径上限为 **94 UTF-16 units**。正式运行时目录名 SHALL 使用由 runtime id 确定性派生的短名（`rt-<12 hex>`），runtime 身份保留在激活记录与 worker 身份中。

#### Scenario: 路径超限拒绝启动
- **WHEN** 用户以 `--data-dir` 指定 data 路径超过 94 UTF-16 units 的 Windows 数据根
- **THEN** 应用拒绝启动，日志与对话框说明当前长度、上限，并建议改用更短目录（如 `C:\ImageStudioData`）
- **AND** 不创建运行时暂存目录、不发起任何网络下载

#### Scenario: 支持范围内路径正常启动
- **WHEN** 数据路径在支持范围内（含默认目录与常规短目录）
- **THEN** 启动、安装、探针与生成行为与加固前一致

#### Scenario: 边界数据根的真实生成
- **WHEN** 数据根 data 路径为 94 units 的边界值
- **THEN** 安装、probe 与真实生成都使用最终运行时路径成功，不出现长路径 DLL/Python 文件错误

### Requirement: 启动失败诊断覆盖数据目录路径错误

数据目录路径长度的启动失败 SHALL 复用现有启动失败诊断（`startup-failure.log`、原生对话框、退出码 3），且日志 SHALL 写入被拒绝的数据根下的 `logs/`（包括未显式指定 `--data-dir` 的默认根），使 release 构建不出现无解释的退出。

#### Scenario: release 构建的可见失败
- **WHEN** 路径超限发生在 release/无控制台构建
- **THEN** 用户能看到中文原因与修复建议，日志保留在对应数据根的 `logs/startup-failure.log` 供排查

### Requirement: 桌面运行日志与失败诊断

宿主 SHALL 在 `<data>/logs/app.log` 写入结构化运行日志：每行包含时间、级别、事件名与关键字段；单文件上限 8 MiB，保留 3 个轮转文件；写入失败 MUST NOT 阻断应用运行。发送链路 SHALL 记录阶段耗时（预检、冻结、取锁、绑定、启动），失败轮次 MUST 在错误详情与日志中同时给出阶段名与耗时。发布构建 MUST NOT 依赖 stderr 才能诊断。

#### Scenario: 发送失败可在日志中定位
- **WHEN** 一次发送在预检阶段失败
- **THEN** `app.log` 中存在该轮次的阶段记录与失败原因，界面错误文本包含阶段名，无需重定向 stderr

#### Scenario: 日志有界
- **WHEN** 应用长时间运行并产生大量日志
- **THEN** 磁盘占用不超过 4 个文件的上限，旧文件按轮转删除

### Requirement: 失败文案准确

轮次状态文案 SHALL 反映真实语义：被拒绝的发送显示"发送失败"而不是"未启动"，并把失败原因作为主要文案；内存或设备预算不足时 SHALL 用中文说明原因并给出可行动建议（例如关闭占用内存的程序后重试）。

#### Scenario: 看门狗拒绝发送
- **WHEN** 一次发送因 60 秒未进入执行被看门狗置为失败
- **THEN** 界面显示"发送失败"及具体原因与重试入口，不显示"未启动"

#### Scenario: 内存预算不足
- **WHEN** 生成前的可用内存低于门槛
- **THEN** 轮次失败文案为中文，说明阈值与实际值，并建议释放内存后重试

### Requirement: Windows 12 GB 标准档在当前主分支上有真机回归证据

Windows 验收 SHALL 在目标 Windows 10 x64 / RTX 3080 Ti 12 GiB 真机上记录当前构建提交、安装包或可执行文件哈希、设备身份和验收档位，并审查当前构建相对既有生图基线是否改变执行面。功能回归完成当前构建的安装、原生界面和本地管理验证，不执行模型推理。完整生图认证 SHALL 在下列任一条件成立时执行：模型、运行时、worker、协议、计划/配方、设备门槛、安装量化或生成提交/恢复链发生变化；既有基线缺失、不完整或不可追溯；所有者明确要求在当前构建上执行完整真实出图验收。完整生图认证 SHALL 覆盖已安装的标准档能力至少各完成一次产品内真实生成、编辑、去背景或放大，记录 CUDA reserved（或按证据口径复用的等价证据）、private commit、可用物理内存最低值、加载/生成墙钟和导出逐字节一致性。未发生执行面变化、基线完整且所有者未要求重新认证时，功能回归 MAY 复用该目标机生图证据，但不得把它改记为当前构建的新实测；其他机器（含 8 GB 补充机）的功能回归、历史生图基线与 CI 结果 MUST NOT 替代目标机当前构建的完整生图认证。

#### Scenario: 仅界面和本地管理变化

- **WHEN** 当前构建相对完整生图基线没有执行面变化，且既有证据绑定目标机、模型/运行时身份和结果文件，所有者也没有要求重新认证
- **THEN** 当前构建可以在完成 Windows 功能回归后声明功能验收通过
- **AND** 报告引用既有生图基线，不下载模型、不运行推理、不生成新图片，也不声称重新完成生图认证

#### Scenario: 所有者要求当前构建的真实出图验收

- **WHEN** 所有者明确要求在当前构建上执行包含真实出图的完整验收，即使 diff 分类为无执行面变化
- **THEN** 在目标 Windows 10 / RTX 3080 Ti 12 GiB 机器上执行完整真实出图验收，覆盖七个型号、八项能力、当前构建的作品/会话管理与真实 v5 数据升级
- **AND** 不得以 8 GB 补充机的功能回归、历史生图基线或 CI 结果替代本轮结果，未执行项保持 `not_run`

#### Scenario: 执行面发生变化

- **WHEN** 当前构建改变模型、运行时、worker、协议、计划/配方、设备门槛、安装量化或生成提交/恢复行为
- **THEN** 必须执行目标机完整生图认证，覆盖受影响的标准档能力并记录原资源、时限、取消/恢复与导出口径
- **AND** 功能回归通过不能替代该认证，未执行项保持 `not_run`

#### Scenario: 基线缺失或差异无法分类

- **WHEN** 找不到完整目标机生图基线，或无法确定 diff 是否改变执行面
- **THEN** 默认要求完整生图认证，不以"可能不受影响"的推断关闭验证

#### Scenario: 证据身份与结论标签

- **WHEN** 验收报告同时引用当前功能回归和历史生图认证
- **THEN** 分别记录当前提交/安装包哈希与历史基线提交/证据路径，并分别标注"功能回归通过"和"生图基线复用"
- **AND** 不得把两类结果合并成"当前构建全部重新认证通过"

#### Scenario: 档位投影与设备身份

- **WHEN** 在完整生图认证要求生效的当前构建上打开模型页
- **THEN** 设备身份显示 RTX 3080 Ti / 约 12,288 MiB / sm86
- **AND** 已安装型号显示 `standard · 1024² · bfloat16`，不出现紧凑档投影
- **AND** Z-Image Turbo 按 12 GB 门槛显示为满足（若已安装则可执行）

#### Scenario: 标准档生成与资源口径

- **WHEN** 完整生图认证要求对已安装的标准档能力发起产品内真实执行
- **THEN** 记录输出 PNG 的尺寸、字节数与 SHA-256，以及 CUDA reserved（或按复用口径标注的等价证据）、进程 commit、可用内存最低值和墙钟耗时
- **AND** 资源口径逐项对照标准档合同（CUDA reserved ≤10.5 GiB、private commit ≤24 GiB、可用物理内存最低 ≥2 GiB、加载 ≤600 s、生成 ≤900 s、无 WDDM 共享内存回退）

#### Scenario: 种子缓存重装与重启恢复

- **WHEN** 完整生图认证要求因激活身份变化拒绝旧就绪记录，随后使用已验证的本地种子缓存重装
- **THEN** 安装记录标注为种子缓存类型并完整记录阶段与耗时，不宣称验证了下载链路
- **AND** 重装后可完成一次标准档生成，导出文件与资产逐字节一致
- **AND** 重启应用后型号仍为就绪，旧作品可重开

#### Scenario: 安装期量化准备被内存预检阻止

- **WHEN** 完整生图认证需要安装量化准备，而本机可用物理内存低于 8 GiB 或 commit 余量低于 6 GiB
- **THEN** 安装器在开始量化前以包含实测值与可行建议的中文错误失败
- **AND** 不留下部分 prepared 缓存或安装记录，且该事件以 `blocked` 记录，不得改写为通过

### Requirement: Panic 钩子链必须同时保留启动失败报告

桌面进程安装的诊断钩子 SHALL 组成单个链，任何后安装的钩子 MUST NOT 使已安装的启动失败钩子失效。链上每个钩子按安装顺序被调用；启动失败钩子命中后以登记退出码结束，不再继续执行后续钩子。

#### Scenario: 日志钩子安装在启动失败钩子之后

- **WHEN** 启动失败报告钩子先安装，日志钩子随后安装，且 Tauri 因 WebView2 或用户数据目录初始化失败而 panic
- **THEN** 进程先写 `logs/app.log` 的 `app.panic` 记录，再写 `logs/startup-failure.log`，显示中文启动失败对话框，并以退出码 3 结束
- **AND** 不会出现只有 101 的静默退出

#### Scenario: 同一数据根的第二个实例

- **WHEN** 一个实例持有数据根，另一个进程用相同 `--data-dir` 启动
- **THEN** 第二个进程按启动失败处理：写 `logs/startup-failure.log`、显示“Image Studio 启动失败”、关闭对话框后以退出码 3 结束
- **AND** 第一个实例的会话、任务、作品与模型安装记录不被修改

#### Scenario: 与启动无关的 panic

- **WHEN** 运行期间发生与 Tauri setup 无关的 panic
- **THEN** 该 panic 除写入 `app.panic` 外，仍按原有默认行为输出回溯，进程不会被执行启动失败流程提前终止

### Requirement: Windows 功能回归不执行模型推理

Windows 功能回归 SHALL 使用当前构建的 x64 安装包和 WebView2 原生应用，验证安装、升级、界面、会话、作品管理、导出、受控删除、设置及启动诊断。该验收 MUST NOT 下载或安装模型、准备私人运行时、启动推理 worker、创建生成任务、执行 GPU 计算或生成新的模型图片。

#### Scenario: 当前构建的纯功能回归

- **WHEN** 变更只影响界面、文档或本地管理，且验收采用 Windows 功能回归
- **THEN** 测试使用既有或隔离的测试数据完成安装与功能操作，不下载模型、不启动生成 worker，也不要求新的图片输出
- **AND** 界面截图、既有作品、日志和文件哈希可以作为证据，但报告明确标注这些不是本轮模型生成结果

#### Scenario: 无模型或网络时的功能可用性

- **WHEN** 应用数据根没有可执行模型或网络不可用
- **THEN** 应用仍可从安装包启动，并完成导航、草稿、既有作品查看/导出、设置与错误状态检查
- **AND** 模型页如实显示未安装/未就绪原因，不因功能验收而自动下载或安装组件

#### Scenario: Windows 文件占用和只读删除

- **WHEN** 测试资产处于只读状态或仍有未关闭的文件句柄
- **THEN** 删除失败显示可重试状态且不虚报成功；解除条件后可完成删除，其他用户文件、外部导出和作品历史保持

#### Scenario: 功能证据不得冒充生图认证

- **WHEN** 功能回归全部通过但未执行模型推理
- **THEN** 结论只声明安装、升级、原生 UI 与本地管理功能通过
- **AND** 不得声明当前构建完成七模型八能力、GPU 资源、图片质量、取消/强杀恢复或性能重认证

### Requirement: Windows 目标机真实出图验收覆盖当前构建的能力矩阵与作品管理

Windows 目标机真实出图验收 SHALL 在当前构建上、在目标 Windows 10 x64 / RTX 3080 Ti 12 GiB 机器内，通过产品界面完成七个已接入型号、八项能力（Klein 文生图与单图编辑、Z-Image 文生图、Qwen-Image 2.1、Qwen-Image 2.1-Turbo、MOSS-Image-SFT、BiRefNet 去背景、Real-ESRGAN 4×）的真实输出；每项 SHALL 记录提示词、模型与执行身份、输出尺寸/字节/SHA-256 与阶段进度。验收 SHALL 使用本轮真实生成的作品验证当前构建的作品查询、筛选、收藏、预览、导出、受控删除、双输出删除、引用阻止/解除、会话删除与作品墓碑；并 SHALL 使用既有真实 v5 数据根的可丢弃副本验证 v5→v6 升级后的作品保留、查看与导出。构造 fixture 或旧文件副本 MUST NOT 被标注为本轮真实生成结果。

#### Scenario: 七型号八能力真实输出

- **WHEN** 执行当前构建的真实出图验收
- **THEN** 七个已接入型号各至少一次成功执行其登记能力，输出为产品内生成并提交的正式作品
- **AND** 每项记录输出尺寸、字节数、SHA-256、提示词、seed 与模型/执行身份
- **AND** 任何失败或未执行项保持 `fail`/`blocked`/`not_run`，不用其他型号或历史图片补位

#### Scenario: 真实新作品进入管理流程

- **WHEN** 本轮真实生成完成
- **THEN** 收藏、筛选、预览、导出、受控删除、双输出删除、引用阻止与解除、会话删除墓碑使用本轮生成的作品验证
- **AND** 导出文件与正式资产逐字节一致，删除后外部导出副本与旧作品历史保持
- **AND** 报告明确区分本轮真实作品与 v5 旧作品副本

#### Scenario: 真实 v5 数据升级

- **WHEN** 使用既有真实 v5 数据根的可丢弃副本以当前构建首次启动
- **THEN** 旧作品、任务、会话与草稿按规格保留并可查看/导出
- **AND** 升级后可重装至少一个型号并完成一次真实生成
- **AND** 迁移失败时不重建空库，无法安全构造的失败保护项记 `not_run`

### Requirement: Windows 目标机真实出图验收的证据口径与结论标签

真实出图验收 SHALL 记录每项能力的产品级证据：提示词与参数、模型与执行身份、输出尺寸/字节/SHA-256、阶段进度、加载与生成墙钟、导出校验；资源证据 SHALL 包含 host 观测的 GPU 使用峰值（注明采样间隔与桌面基线）、生成进程树私有提交峰值、可用物理内存最低值与对应阈值。worker 内部 CUDA reserved 未被产品持久化时，所述证据 MAY 由同一执行面的历史 Gate 0 记录承担，但 SHALL 显式标注"复用"及基线提交/路径；执行面发生变化时该复用无效，相关项 SHALL 记为 `not_run` 并另行认证。每项状态 SHALL 为 `pass`/`fail`/`blocked`/`not_run`；人工复核项 SHALL 记录操作者与结论；报告 MUST NOT 把复用证据、其他机器结果或功能回归写成当前构建的实测通过。

#### Scenario: 产品级资源采样

- **WHEN** 一次真实生成正在执行
- **THEN** 以固定间隔采样 GPU used、生成进程树私有提交与可用物理内存并保存原始 CSV
- **AND** 汇总 JSON 注明采样方法、桌面基线与阈值，不宣称达到 worker 内部精度

#### Scenario: 复用 Gate 0 资源口径

- **WHEN** 产品未持久化 worker CUDA reserved 且执行面 diff 审计为无变化
- **THEN** 引用历史 Gate 0 证据并标注复用，产品级预算用 host 观测口径对照
- **AND** 不把历史 Gate 0 数字写成当前构建的新实测

#### Scenario: 至少一条真实网络安装路径

- **WHEN** 本轮需要验证真实下载链路
- **THEN** 在空缓存根真实下载并安装至少一个大型模型（例如 Z-Image Turbo），记录每个 artifact 的 URL、声明/实际字节、SHA-256、耗时、吞吐与代理环境
- **AND** 其余安装 MAY 使用已验证种子缓存并标注 provenance，下载耗时不得混入缓存安装耗时
- **AND** 网络不可用或校验失败时记 `blocked` 或 `fail`，不冒充安装或出图通过

#### Scenario: 人工复核与未执行项

- **WHEN** 视觉质量、真实 IME 或显示缩放依赖人工操作
- **THEN** 机器检查与人工复核分开记录；所有者可明确放弃人工项，报告 SHALL 以 `waived`/`not_run` 记录决定来源
- **AND** 未执行或放弃项不得写成通过，也不得据此声明视觉质量或输入法已验收
