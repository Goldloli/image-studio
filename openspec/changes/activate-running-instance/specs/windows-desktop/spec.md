## MODIFIED Requirements

### Requirement: Windows 目录和受控文件操作可可靠使用

应用 SHALL 在当前用户的本地应用数据位置解析独立 data/cache/logs/work 目录，支持 `--data-dir` 隔离根与按数据根的单实例。登录会话内同一数据根的第二次启动 SHALL 激活已运行实例的主窗口（还原最小化窗口并置于前台）并以成功状态退出，MUST NOT 构造第二个宿主、打开第二套 WebView2 用户数据目录，也 MUST NOT 让用户看到 WebView2 初始化错误形式的启动失败。激活在 1.5 s 内无法确认时，第二次启动 SHALL 以“已在运行但未响应”或“数据目录正被另一个实例使用”的明确原因提示并按成功状态退出，不得改写数据库或启动另一套模型执行。中文、空格和合法特殊字符 SHALL 原样通过原生路径与进程参数；不可写、无效、受占用或逃逸管理边界的路径 SHALL 明确拒绝并保留已有数据，不回退源码目录。候选和导出 SHALL 保持普通文件、路径归属、内容验证、覆盖确认及失败不损坏旧文件的合同。

#### Scenario: 中文用户名与安装目录
- **WHEN** 用户目录、安装目录或隔离数据根包含中文和空格
- **THEN** 应用能启动、保存并重开会话、运行受管程序及导出 PNG，路径不被解释为命令

#### Scenario: 同根第二实例
- **WHEN** 用户在已有实例运行时再次启动，且两次使用同一数据根（允许路径大小写与短文件名差异）
- **THEN** 第二次启动不打开数据库、不创建 WebView2 用户数据目录，已运行窗口被还原并置于前台，第二个进程以退出码 0 结束
- **AND** 不出现“Image Studio 启动失败”，第二次启动不写 `logs/startup-failure.log`

#### Scenario: 同根实例无响应或位于另一登录会话
- **WHEN** 同一数据根的另一个实例存在，但在 1.5 s 内未确认激活（无响应，或属于另一个 Windows 登录会话）
- **THEN** 第二次启动显示说明该情况的中文原生提示并以退出码 0 结束，给出“结束该进程后重试”的动作
- **AND** 数据库、作品与模型安装记录不被第二个进程改写，不并发启动第二套模型执行

#### Scenario: 不同数据根的两个实例
- **WHEN** 第二个宿主使用不同的 `--data-dir` 同时启动
- **THEN** 两个实例各自使用属于自己的 WebView2 用户数据目录并按各自数据根工作，不因共享浏览器 profile 或缓存互相中断

#### Scenario: 重解析路径或目标被占用
- **WHEN** 候选/导出路径越界、包含逃逸重解析点或目标无法安全写入
- **THEN** 操作失败且说明恢复动作，旧目标、正式资产与制作记录保持完整
