## Goals / Non-Goals

**Goals:**

- 完成全量案例的可追溯迁移，用户能看图、分类查找、收藏并使用原文提示词。
- 文字目录完全本地可用，图片联网按需加载，已缓存图片断网可查看。
- 保持现有会话和真实生成语义，明确上游示例不等于本机生成。

**Non-Goals:**

- 本阶段不做交易、投稿、评论、账号、榜单或付费内容。
- 不移植上游完整网站、2.5 比较专区、生成 API、模板引擎、Skills 执行或订阅服务。
- 不因提示词来源而接入 GPT Image，不提供参考图编辑执行，也不承诺本地模型复现原图。
- 不做应用内自动更新、全库预下载、用户自建提示词编辑器或自动翻译服务；后续扩展另行提案。

## Decisions

### 1. 命名与入口

采用「灵感库」。它同时覆盖图片效果与提示词的浏览用途，也可扩展到其他来源。备选「示例提示词」较长且弱化图片，「提示词市场」容易让人期待交易，「灵感广场」容易让人期待用户发布。

导航建议为「创作 → 灵感库 → 功能 → 模型 → 作品 → 任务」，设置维持底部。使用与现有界面一致的线性图标和主题色，不新增绿色视觉体系。灵感库拥有独立的页面标签和页内分类区，不占用创作会话列表。

### 2. 页面与主要路径

页面顶部为标题、搜索、可见结果数；视图切换为「全部 / 精选 / 我的收藏」。主分类作为页内分类栏，风格和场景放入筛选面板，避免同时铺开所有标签。卡片只显示图、标题、主分类、必要使用条件及收藏；点击进入详情。

建议布局：

```text
主导航 │ 灵感库                  搜索标题、提示词、标签…
       │ 全部  精选  我的收藏          风格 / 场景 / 排序
       │ 分类        图片卡片   图片卡片   图片卡片
       │ 海报排版    标题/分类  标题/分类  标题/分类
       │ 摄影写实    图片卡片   图片卡片   图片卡片
       │ ……
```

1280×800 目标为分类栏加三列卡片；960×640 收起分类栏为筛选控件并保留两列。采用规则网格和固定预览框，图片等比完整显示，避免裁掉海报文字；详情可放大原图。详情在宽窗并排展示图片和提示词，窄窗转为可滚动布局，操作入口始终可达。此为布局目标，需在实施时原生验证。

详情包含：标题、示例图片、主分类及标签、完整原文提示词、变量/参考图说明、来源作者、原帖（如有）、GitHub 案例链接，以及「复制提示词」「使用提示词」「用于当前会话」「收藏」。按钮「使用提示词」旁明确写明“新建会话，不自动生成”。提示词用纯文本渲染，不执行或解释其中的 HTML、命令、JSON 指令。

返回列表恢复搜索、筛选、排序与滚动位置；切换到创作再返回也保持。应用重启恢复收藏，首版不要求恢复搜索或滚动。

| 摄影与写实 | Photography & Realism | 78 |

| 图表与信息图 | Charts & Infographics | 53 |

| 角色与人物 | Characters & People | 31 |
| 品牌与标志 | Brand & Logos | 27 |

搜索覆盖标题、提示词全文、中英文分类、风格、场景和来源作者，按空白分词，词之间 AND，单词在任意字段命中即可，英文不区分大小写。主分类单选，风格和场景可多选，同维度 OR、跨维度 AND；与搜索、精选、收藏条件共同取交集。零结果给出「清除筛选」。

默认排序为精选优先、再按上游编号倒序；可切换「案例编号倒序」或「案例编号正序」。不以编号推断实际生成日期，不制造“热门”或使用人数。中文显示合并 Character/Characters、Product/Products 的同义风格，保留原始标签用于追溯，不自动把不同语义的风格合并。

### 4. 迁移与内容模型

维护时读取固定提交的 `data/cases.json`，不从长 Markdown 或网页 DOM 抓取主要数据。`data/style-library.json` 只辅助中文标签，不把工业模板混入案例列表。

建议生成 `resources/prompt-library/catalog.json` 作为唯一规范化目录，头部包含 `schemaVersion`、`catalogVersion`、`upstreamRepository`、`upstreamCommit`、`importedAt`、`sourceCount`、`importedCount`。每条至少包含：

| 字段组 | 内容 |
| --- | --- |
| 身份 | `id=awesome-gpt-image-2:case:<原编号>`、`sourceCaseId` |
| 内容 | `title`、`prompt` 原文、`imageAlt`、`featured` |
| 分类 | 稳定主分类 ID、原始分类、规范化风格/场景及原始标签 |
| 图片 | 固定提交下 `data/images/<文件>` 的路径、文件散列与字节数；不接受任意用户 URL |
| 来源 | `sourceLabel`、可空 `sourceUrl`、固定提交的 GitHub 案例链接、上游许可及第三方声明的引用 |
| 使用条件 | `inputKind=text-to-image/image-edit/reference-image/unknown`、`hasVariables`、人工使用说明、审核状态 |
| 模型信息 | 上游目录归类及验证状态；无逐条证据时不填精确模型 ID、种子、尺寸或本机兼容保证 |

原文不翻译、不截短、不去掉变量，不把预览短句 `promptPreview` 当全文。原始编号、内容散列和上游提交支持后续差异比较。人工分类或说明存于独立修正表，重新导入不能覆盖人工字段。

导入报告至少检查总数、唯一 ID、必填字段、分类、全部图片映射与文件散列，以及 25 个空原帖链接。空原帖使用 GitHub 案例入口兜底，界面显示「未提供原帖」，不伪造地址。异常条目必须逐项进入报告，不允许静默丢弃；初次交付目标是 541 条完整目录。

只读取迁移所需数据和图片，不引入上游支付、账户、埋点或生成代码。内容包保留上游 LICENSE 和来源声明；第三方示例不统一标为 MIT 可商用。分发时按对应来源条件处理，有明确分发限制的图片保持条目与来源入口但不打包或缓存，受影响条目在报告和界面如实说明。

### 5. 图片、离线与缓存

选择「本地目录 + 图片按需获取与缓存」，而不是把约 150 MiB 原图加入安装包。用户未进入灵感库时不请求图片；进入后只加载可见卡片与一屏预取，详情按需读取相同原图。首版不提供全库后台预下载。

宿主接受案例 ID 与图片用途，根据内置清单解析固定提交的 GitHub 图片地址；拒绝任意路径、任意 URL 和未登记 ID。远程 IO 与解码不占用 UI 绘制路径，不持有主作品库锁等待网络。下载并发上限初始为 4、单请求超时 20 秒、单文件 16 MiB、解码像素上限 6400 万；这些是待验证的防护预算，不是性能实测结论。重定向仍检查目标来源。

缓存位于应用数据根下独立 `cache/prompt-library/`，不进入项目的正式资产目录。文件先写临时位置、检查大小/格式/散列后原子提交，通过专用受限本地图片协议提供给 WebView；不扩大 CSP 到所有远程域名。卡片可使用本机派生缩略图，详情使用已验证原图。下载失败的部分文件不成为可读缓存。

缓存预算初始为 256 MiB，以最近读取淘汰；当前正在查看的文件受保护。页面菜单提供缓存占用与「清理图片缓存」，不删除目录、收藏或正式作品。首次断网时仍能搜索、看全文、复制、收藏和填入草稿，未缓存图片显示“联网后加载示例图”；已缓存图可离线查看。图片失败给出重试和来源入口，不产生全局阻塞弹窗。

### 6. 收藏与目录更新

收藏采用独立版本化 `prompt-library-state.json`，保存稳定案例 ID，复用现有偏好存储的原子写入方式；不为 541 条静态内容新增数据库表或独立 crate。写入失败保留既有文件并回滚收藏视觉状态，解释未保存；损坏文件读取后报告错误，不在加载时覆盖。

首版目录随应用发布，更新由维护者显式执行导入并审核差异，再随版本交付。不内置 GitHub Token，不在启动时查更新。同 ID 更新保留收藏；移除案例保留其收藏标识，在收藏页显示不可用占位及可取消收藏入口，不产生指向其他案例的错误映射。

### 7. 从案例进入创作

主路径为「使用提示词 → 保存当前已确认草稿 → 新建会话并原子写入案例原文 → 导航到新会话并聚焦输入」。新会话使用现有默认值解析器，不从当前会话继承瞬时型号，也不因为上游案例属于 GPT Image 而切换模型。新会话标题可用案例标题，创建时明确保存初始文本；不创建 Turn、Job、Attempt 或 AssetRef。

为避免“先建空会话、再填词失败”的中间状态，建议给现有创建入口增加受限的初始提示词/来源案例输入，宿主验证后在同一事务创建会话、草稿及来源信息。若已有创建契约可承载初始文本，则复用。普通新建仍为空白；不改变现有调用方默认行为。

次路径「用于当前会话」锁定用户点击时的目标会话 ID 和草稿版本。目标为空则填入；与原文完全相同则仅定位输入；有不同内容则提供「替换 / 取消」，一次撤销可恢复原文。等待确认或保存期间版本已变化时重新读取并提示，不把旧确认用于新内容，也不改写后来切换到的会话。取消没有副作用。

所有路径先检查 IME 与保存队列：仍在组合时请用户先确认候选；保存失败时留在来源页且保留草稿。以一次性意图 ID 消费导航请求，重复点击进行中锁定，重挂载或切页不得再次创建会话、填词或打开旧查看器；失败可明确重试。

参考图/编辑类与未知类仍可复制及填入草稿，详情在操作旁说明“该案例需要参考图或编辑能力，当前仅填入文字”。不以示例结果图充当参考图、不自动上传图片、不启用尚未支持的编辑能力。模板保留变量并提示先替换；不自动推断种子、画幅或执行参数。当前模型的生成禁用与参数检查保持有效。

### 8. 模块边界与验证

前端建议新增 `PromptLibrary.tsx`、目录查询纯函数及专用样式；`App.tsx` 只协调页面和意图，`Workspace.tsx` 复用草稿保存/应用流程。宿主在现有适配层增加目录、收藏和图片缓存模块，依赖方向为 UI → 受限宿主服务 → 内置目录/本地状态/固定图片源，不能反向依赖推理执行器。不新增服务进程或独立 crate。

UI 查询、筛选和列表状态在本地执行；宿主提供目录、收藏写入和图片读写。接口设计围绕案例 ID，具体命名在实施阶段保持现有命名约定。浏览器预览读取同一目录的构建资源，收藏若为临时状态必须明示；原生持久与协议路径必须另做验证，预览不能代替桌面验收。

验收覆盖目录完整性、筛选交集、原文复制、缺图/超时、离线缓存、收藏重启、缓存清理隔离、草稿覆盖确认/撤销/版本冲突、创建幂等、后台生成期间浏览及 1280×800/960×640 亮暗主题。此功能不需要新模型下载；真实生成只沿用已就绪模型检验“填词后显式发送”的原有路径，不以是否复现 GPT Image 图片作为通过条件。

## Risks / Trade-offs

- 首次图片访问依赖 GitHub 网络，体验不等于全离线图库；采用明确占位、重试与缓存，完整离线包留待后续提案。
- 上游标签存在噪声，部分场景标签覆盖过宽；主分类优先，中文同义映射与人工修正分离，不把自动标签当作能力证明。
- 上游 MIT 不能替代第三方图片和提示词各自的来源条件；保留逐条署名与声明，对明确受限条目提供来源入口和处理记录。
- 初始快照与之后的上游内容可能不同；页面提供数据版本说明，实施若改用新提交须重新核对数量、映射与差异报告。
- 同一工作区已有其他未提交改动和进行中 change；实施时先核对最新导航/发送逻辑，只合并本 change 所需部分，不覆盖其他工作。
