## Context

当前 `App.tsx` 只有创作、模型、任务和设置四个页面；任务列表直接使用最新 `StudioSnapshot.jobs` 并轮询固定 offset，状态标签只是不可点击的 span，制作记录把 manifest JSON 放在 `<pre>` 中。资产只通过创作页的作品条和任务缩略图出现，没有跨会话作品查询。模型和会话能力分别由两个前置 change 打底，本 change 不应复制它们的身份或状态。

## Goals / Non-Goals

**Goals:**

- 将功能、作品和任务页面建成现有业务事实的查询投影，跨页面保持 Conversation、Turn、Job、Attempt 和 AssetRef 身份。
- 让列表计数、筛选和分页在宿主完成，并让空态、读取失败和局部资源异常可区分。
- 让文生图从功能页回到统一 composer；其他未实现功能只说明边界。

**Non-Goals:**

- 不新增图片推理执行器、任务队列或隐藏的后台重试。
- 不为作品、任务或功能建立第二份业务历史。
- 不扫描任意图片目录，不实现收藏、标签、批量操作或删除。

## Decisions

### 1. 页面是登记和查询投影

新增三个受限业务查询：

- `feature_catalog`：返回产品功能登记及依赖条件；
- `asset_library_query`：返回正式 AssetRef 结果和有界分页信息；
- `task_center_query` / `task_center_detail`：返回任务摘要、当前 Attempt、结果和结构化详情。

前端不读取 SQLite、manifest 目录或模型文件自行组装。功能状态依赖模型 change 的目录投影；作品和任务依赖归档后的 Conversation/Turn 关联。页面查询不得写任务、资产、草稿或聊天记录。

### 2. 功能目录使用版本化能力定义

功能条目由宿主资源定义，字段包括稳定 `featureId`、输入/输出 contracts、所需模型能力、计划/接入状态和范围说明。首批仅 `text-to-image` 接入；edit/remove-background/upscale 只有计划信息。

可用性从模型目录和当前会话条件派生，功能资源不保存 `ready` 布尔值。任何执行入口指向现有统一提交入口；功能页本身不调用 worker。后续源图功能只接受受限 AssetId、角色和已知参数，输出另存新资产。

### 3. 作品查询复用正式资产与 manifest

`asset_library_query` 以已有不可变资产表/manifest 为来源，联合 Conversation/Turn/Job/Attempt 的持久来源身份。分页键使用 `(created_at, asset_id)`，结果总数与同一筛选条件一起返回。缩略图只通过受控 asset URI 加载，前端不获得真实文件路径。

作品项目录不含示例、候选和临时文件。用户导出调用现有原生保存能力；该动作写用户选择目标，不修改原资产。缺失文件只在查询 DTO 中标记 `unavailable`，原有成功 manifest 保持不变。

### 4. 任务中心统一宿主查询和详情

`task_center_query` 接受状态集合、文本、会话、模型、limit/cursor；宿主产生列表和同条件 counts，排序使用稳定任务身份。`task_center_detail` 返回可读摘要、来源、当前与历史 Attempt、阶段/错误、资产可用性和有界高级数据。完整 manifest/日志只在用户展开时按需读取，避免默认页面加载大对象。

取消和重试继续调用现有业务命令，传入持久 JobId/AttemptId。页面不实现自己的状态机；动作后的本地“正在取消”仅作为命令在途提示，持久状态查询仍为权威。

### 5. 跨页返回使用显式目标上下文

路由状态保存目标页、来源 featureId、ConversationId、TurnId、AssetId 或 JobId 和必要查询条件。进入创作时先切换会话再定位轮次/输入焦点；返回来源页恢复筛选、滚动锚点与选中项。

从功能页进入文生图必须定位当前会话 composer；从作品或任务打开资产只切换查看器，不自动改成新会话。异步查询结果带请求代次和来源页，迟到响应不能覆盖当前页。

### 6. 空态按事实分类

页面先判断全局查询是否成功，再判断“无记录”“无匹配”“局部资源异常”“模型缺失”“正在执行”。全局读取失败保留最近可见数据并提供重试；单条失败不拖垮整页。空态主动作分别指向创作、清除筛选、模型详情或重试。

### 7. 页面布局保持现有桌面骨架

继续使用顶部标签、窄图标导航和主表面。功能页采用分类导航+能力列表/详情；作品页采用筛选条+自适应网格+预览；任务页采用查询条+结果列表+可折叠详情。960×640 下允许侧栏收起或详情改为抽屉，保留主操作和返回入口。

## Risks / Trade-offs

- [前后两个主规格尚未归档导致身份字段不一致] → 本 change 明确阻塞于会话和模型/设置 change；实施前重新读取主规格并调整 delta/tasks。
- [任务查询与实时快照出现新旧状态交错] → 所有结果携带持久 ID/版本和查询代次，前端不按提示词合并。
- [作品缩略图请求过多] → 宿主分页、前端并发/视口加载和局部失败隔离。
- [状态筛选计数昂贵] → 先加必要索引并按查询计划验收；稳定游标避免深 offset 重复。
- [功能页看起来像已有多个产品能力] → 接入状态和依赖由宿主登记驱动，计划中能力没有开始动作。
- [返回上下文过多导致路由复杂] → 只保存业务 ID、来源页和有界浏览状态，不保存大型结果对象。

## Migration Plan

1. 当前会话 change 与模型/设置 change 完成并归档后，重新读取它们的 DTO、主规格和任务结果。
2. 先上线只读功能、作品和任务查询及索引，不改变现有生成/资产数据。
3. 添加页面路由和组件，逐步把任务页现有列表、作品条入口和模型状态消费切到新查询。
4. 保留现有单页与命令作为回滚路径；新页面只读事实可隐藏，不回滚或删除业务记录。
5. 源图功能不在本 change 中启用；未来每个模型/工具以独立 change 增加输入、输出和实机验证。

## Open Questions

无影响规格或任务拆分的问题。功能卡排版、网格列数和抽屉宽度可在获批后的视觉验收中调整。
