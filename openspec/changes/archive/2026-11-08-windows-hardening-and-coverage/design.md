# Design: windows-hardening-and-coverage

每条建议都来自本会话的真实观测，逐条给出证据与方案。

## 1. 可观测性

### 1.1 GUI 没有日志文件

**证据**：本轮定位"每次发送卡 60 s+"时，`eprintln!` 的输出在 GUI 进程里完全看不到；只能先用 `Start-Process -RedirectStandardError` 重启应用才拿到分段追踪。发布版本里用户与支持人员没有这条路径。

**方案**：宿主启动时打开 `<data>/logs/app.log`，写入结构化行（时间、级别、事件、字段），单文件上限 8 MiB、保留 3 个轮转文件；`eprintln!` 的逐段追踪改为 `tracing`-风格的事件（或最小自研 logger），默认 INFO，`--diagnostics` 时 DEBUG。

**验收**：跑一次发送，日志里能看到 `preflight` 各阶段耗时与 `bind` 用时；失败轮次能在日志里定位到阶段。

### 1.2 失败轮次不记录阶段耗时

**证据**：看门狗产生的错误是「发送超时：60 秒内未进入执行（等待提交阶段）」，但不知道卡在 freeze、锁还是 bind。

**方案**：`prepare_turn` 记录各阶段 `Instant`，失败时把阶段名与耗时并入错误详情（界面可见），同时写日志。

## 2. 文案与交互

### 2.1 `Rejected` 显示「未启动」

**证据**：`studio-api.ts` 的 `stateLabel` 把 `Rejected` 映射为「未启动」；实际语义是"发送失败"，用户看到「未启动」会以为是没点到。

**方案**：改为「发送失败」，并把失败原因作为主文案（当前原因已存在，只是被状态标签压住）。

### 2.2 内存预算拒绝的文案生硬

**证据**：一次真实失败显示 `budget exceeded: available RAM 0.791 GiB < 2.0 GiB`（英文、无建议）。

**方案**：改为中文、给出建议（"关闭占用内存的程序后重试"），并在轮次上提供「重试」按钮（已有）。

### 2.3 取消等待已可见（本轮已实现）

`cancelLabel` 每秒刷新，超过 15 s 提示"进程可能仍在回收"。无需追加工作。

### 2.4 待确认：模型选择器点击未观察到菜单

**证据**：点击 `.model-select` 后 `aria-expanded=true`，但 DOM 中没有任何模型列表；最终通过模型页的「用于当前会话」切换成功。

**判断**：可能是选择器未渲染、也可能是测试时序问题。**需要一次人工确认**，确认是 bug 后单独修。

## 3. 测试工具

### 3.1 CDP 缺文件选择命令

**证据**：Klein 编辑需要「导入源图」，走 `rfd` 原生对话框；`cdp.mjs` 只有 eval/click/type/shot，无法注入路径，导致编辑路径无法脚本化。

**方案**：给 `cdp.mjs` 增加 `files <selector> <path>`（CDP `DOM.setFileInputFiles`）与 `dialog <path>`（复用 `save-ui-dialog.ps1`）两个命令；若导入始终是原生对话框，则用 UIAutomation 封装。

### 3.2 端到端脚本套件

**方案**：把本轮手工流程固化为 `scripts/windows-ui/scenarios/`：`send-export.ps1`（发送→查看→导出→比对字节）、`cancel.ps1`（取消计时）、`kill-recovery.ps1`（强杀→重启→恢复）、`install.ps1`（安装→阶段记录）。

## 4. 未触发的分支

### 4.1 取消的强制回收

**证据**：三次取消都在 5.1–6.7 s 内合作退出，`force_killed` 分支从未执行。

**方案**：写一个 stub supervisor（忽略 cancel 消息、持续休眠），在集成测试里触发强制回收，断言 `cancelled` 落定与进程组回收。

### 4.2 真实网络故障下的下载重试

**证据**：注入故障需要防火墙/hosts（管理员权限，本会话没有）。

**方案**：为诊断构建提供 `--download-fault <attempts>` 开关（仅 `--diagnostics` 生效），让每次安装的第 N 次尝试强制失败；或在 CI 里用本地 HTTP 代理注入。默认发布构建不包含该开关。

### 4.3 看门狗超时

修复后无法自然复现。用 4.1 的 stub 思路：人为让 `bind_turn_job` 阻塞（测试专用钩子）验证 60 s 落定。

### 4.4 防回归：发送路径不得重新哈希

**方案**：加一个测试，把已就绪的安装目录设为"内容不可读"（例如只保留元数据），断言 `ready_paths()` 仍成功——若将来有人把哈希加回快路径，测试会失败。

## 5. Windows 专属回归（本分支改动后未复测）

| 项 | 来源 | 判定 |
|---|---|---|
| 100%/150%/200% DPI、960×640 / 1280×800 布局 | windows-desktop 规格 | 截图 + 元素可见性检查 |
| 中文 IME 组合确认不误触发送 | windows-desktop 规格 | 手动/自动化按键序列 |
| 原生导出对话框 | 作品页导出 | 对话框自动化 |
| 磁盘不足 | model-installation 规格 | 用小分区或配额模拟 |
| 非 ASCII / 长路径 | 数据目录 | 在含中文与长路径的目录下跑一次安装+生成 |
| 多显示器 / 睡眠唤醒 | 桌面应用 | 手动 |
