# Proposal: simplify-redundant-ui-copy

## Why

全站审计发现，创作、灵感库、模型、作品和设置页面普遍用眉标、副标题、重复计数和辅助小字解释布局已经能表达的信息，挤占了视觉层级与交互设计的注意力。现在需要把“避免不必要的辅助标签与说明，让布局本身发挥解释作用”固化为可验证的界面契约，并在不删除必要来源、许可、安全与错误信息的前提下完成一次统一精简。

## What Changes

- 建立全站布局优先的呈现规则：同一信息只在一个主要位置出现，优先用分组、层级、图标、筛选选中态和状态表达含义；不得用装饰性英文眉标、通用副标题或重复标题再次解释页面。
- 精简创作页：移除重复品牌眉标和通用步骤说明，收敛会话标题、字符数、快捷键、模型状态和保存状态的常驻文案；图片点击行为不再用覆盖层文字重复说明。
- 精简灵感库与案例详情：目录来源和“上游示例”只保留一个主要说明位置，移除重复案例总数和逐卡重复徽标；分类、来源、参考图条件与许可信息按任务优先级组织，必要证据改为次级展开或局部说明。
- 精简模型页与模型详情：侧栏筛选计数不再与顶部统计条重复，移除静态“本地模型库”标签和通用副标题；安装、运行时、设备、许可和来源按“首要状态、可行动信息、可展开证据”分层。
- 精简作品页与制作记录：移除 `AssetRef` 等开发术语作为页面眉标和常驻元数据；同一提示词、会话、型号、尺寸、种子与时间只显示一次，原始 Job/Attempt/Asset ID 和重复摘要进入高级详情。
- 精简设置五个子页：移除跨分组重复的通用副标题与无信息量的分组标签，合并同义页标题和区块标题，减少字段辅助小字；存储可用空间等全局信息只显示一次。
- 保留并降低视觉噪声：删除确认、来源与许可、非本机生成、硬件门槛、保存失败、资源异常和恢复动作等必要说明 MUST 继续可读、可访问，不得因精简而丢失。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-workspace`：定义全站布局优先的呈现原则，并精简创作页导航、空状态、画布提示和输入区辅助文案。
- `prompt-library`：收敛灵感库目录来源、示例身份、计数、使用条件与详情元数据的重复表达。
- `model-catalog`：收敛模型页统计、筛选、状态、许可、来源和详情证据的信息层级。
- `asset-library`：收敛作品卡片、预览与制作信息中的重复标题、状态和技术身份。
- `task-center`：让制作记录保留一次请求摘要，技术标识与 manifest/日志只在高级详情中出现。
- `application-settings`：统一五个设置子页的标题层级、辅助说明、存储统计和运行环境状态表达。

## Impact

- 前端涉及 `App.tsx`、`Workspace.tsx`、`PromptLibrary.tsx`、`ModelLibrary.tsx`、`AssetLibrary.tsx`、`ProductionRecord.tsx`、`SettingsPage.tsx` 及对应样式和组件测试。
- 不修改宿主命令、持久化 schema、模型目录身份、生成请求、导出、删除或运行时行为；现有功能、数据和可访问名称保持可用。
- 本阶段只提交 OpenSpec 文档；用户确认前不得修改实现代码、正式规格或归档 change。报告证据保存在 `target/audit/layout-labels-20261113/`，仅用于本次设计与验收，不替代正式规格。
