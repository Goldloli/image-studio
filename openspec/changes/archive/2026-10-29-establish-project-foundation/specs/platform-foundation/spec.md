## Purpose

使基础应用在当前 macOS 开发环境具有明确且可验证的目录、进程和构建行为，并把业务身份与平台路径分开，为后续 Windows 适配保留可复用核心。该能力的验收范围是开发构建和平台边界，不代表应用分发或任何模型硬件认证。

## ADDED Requirements

### Requirement: 平台路径通过统一边界解析

应用 SHALL 通过平台适配入口获取应用数据、缓存、日志和诊断临时目录，支持测试时显式指定隔离数据根。领域身份 MUST 不依赖这些目录的绝对字符串；目录不可写时 SHALL 报告具体操作及可采取的动作，不能静默改写到源码目录。

#### Scenario: 路径包含中文和空格
- **WHEN** 开发者使用带中文和空格的隔离数据根运行应用与诊断
- **THEN** 目录和进程输入正确解析，不截断路径或把路径的一部分解释为命令

#### Scenario: 数据目录不可写
- **WHEN** 应用需要的目录无法创建或写入
- **THEN** 应用报告存储位置错误及修复方向，保持已有文件完整

### Requirement: 进程通过参数与受管理生命周期启动

应用 SHALL 直接使用进程 API 和独立参数启动其明确选择的诊断程序，不能经用户 shell 拼接命令。worker 及其测试后代 SHALL 归入可清理的受管理生命周期；进程回收与 UI 绘制 SHALL 解耦。

#### Scenario: 可执行路径含命令特殊字符
- **WHEN** 诊断程序位于包含空格、中文和 shell 特殊字符的合法路径
- **THEN** 应用仅启动该程序并原样传入参数，不执行路径中的额外命令

### Requirement: 工程可从干净检出重复验证

项目 SHALL 提供固定 Rust 工具链、依赖锁及非交互构建与检查说明。在安装了说明中工具链和目标组件的环境中，开发者 SHALL 能构建桌面壳及诊断 worker，并执行格式、静态检查和契约/协议测试。构建成功 MUST 不依赖源码仓库外未声明的个人图片、模型、Python 环境或绝对路径。

#### Scenario: 干净检出构建
- **WHEN** 开发者在具备说明中构建依赖的干净检出中按文档执行检查
- **THEN** 所列命令可非交互完成并生成声明的开发构建；依赖可下载时不额外下载模型或推理运行时

### Requirement: 核心与协议具有有限且准确的跨平台证据

核心与协议库 SHALL 在 macOS 本机构建检查之外，通过 Windows x64 目标的编译检查。验证记录 SHALL 明确这是编译证据，未在 Windows 验证的 GUI、进程、设备和模型能力 MUST 保持未验证状态。

#### Scenario: Windows 目标编译检查通过
- **WHEN** 在已安装对应 Rust 标准库目标的环境中对核心与协议执行 Windows x64 编译检查
- **THEN** 两个库通过编译检查，交付记录仅报告这两个库的目标编译结果
