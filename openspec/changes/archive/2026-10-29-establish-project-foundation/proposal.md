## Why

Image Studio 已有完整研究，但还没有应用实现或正式基础规格。首先明确架构边界、数据契约和工程验证方式，建立一个可构建、可检查的最小底座，使后续真实生成、编辑和模型接入能够沿相同边界扩展。

**状态：用户于 2026-10-29（Asia/Shanghai）明确回复“开始”，批准按本提案实现基础框架。实现及验证使用 Beads epic `image-studio-1q8` 跟踪；审批不扩大到本提案范围外的模型、运行时或后续功能。**

## What Changes

- 建立可独立构建的 Rust 桌面入口、应用核心与 worker 协议边界；核心不依赖 GUI 或具体推理实现。
- 提供无模型也能使用的桌面壳，验证中文提示词输入、窗口布局、后台消息和准确的“尚未配置推理”状态。
- 建立项目、资产、用户请求、执行计划、Job/Attempt 和制作记录的最小类型契约，验证身份、版本、输入角色和序列化规则。
- 建立受管理的诊断 worker，验证握手、协议版本、会话与序号、探针、超限及错误消息、退出和清理；诊断成功只表示通信链路通过。
- 建立 macOS 路径与进程适配边界，以及核心/协议的 Windows 编译检查和本地质量门禁。

### Proposed baseline for approval

以下是本提案提出的选择，不是用户此前已经确定的技术决策：

| 项目 | 本次拟采用的方案 | 验证或限制 |
|---|---|---|
| 平台 | 当前 macOS 开发机；实现时记录真实架构与系统版本 | 本次无 GPU 推理，不据此确定模型硬件范围或最低系统要求 |
| 界面 | Rust + egui/eframe，中文优先 | 通过输入法、文本编辑、窗口缩放和后台响应验证后，作为后续界面起点 |
| 工程 | Cargo workspace；desktop、studio-core、worker-protocol 与诊断 worker 四个成员 | core 内先用模块组织领域和应用职责；按真实需求再拆 crate |
| 通信 | 受管理子进程 + 有界 JSON Lines 协议 v1 | stdout 传协议，stderr 传日志；本阶段只支持诊断，不支持生成 |
| 数据 | 类型化 ID、独立 schema 版本、用户请求与实际执行记录分离 | 先验证契约，不实现数据库、文件对象库或完整任务状态机 |
| 平台扩展 | 平台目录与进程操作集中在 adapter；核心/协议编译检查 Windows x64 | 该检查不等于 Windows GUI、worker 或 GPU 已验证 |

上述方案获得批准后才开始搭建。若 egui 无法满足基础输入门禁，应提交证据并修订设计，经确认后调整框架。依赖和工具链在实现起点精确锁定，并记录验证环境；本提案不声明已验证的库版本。

SQLite、MLX/MFLUX、可选 Python runtime、首个模型、模型下载策略及公开分发方式继续作为后续 change 的决策事项。批准本 change 不等于批准这些实现。

### Milestone and acceptance

本 change 完成的最小演示是：**从干净检出构建 → 断网启动桌面壳 → 输入并编辑中文提示词 → 明确看到尚未配置推理 → 在开发诊断入口启动 worker → 查看握手与探针结果 → 停止并确认进程清理。**

同时通过核心契约校验、序列化兼容性、协议异常与进程退出测试，以及核心/协议的 Windows 编译检查。验收结果仅标记“基础框架通过”，不能标记“图片生成完成”或任何模型 C3–C5 认证。

### Non-goals

- 模型安装、真实推理、下载器、生成调度、资产持久化和重启恢复属于下一阶段真实生成闭环。
- 图片导入导出、画布缩放、图层、蒙版与专业编辑按后续场景逐项增加。
- 插件 SDK、节点编辑器、ComfyUI、远程执行、训练和协作保留在研究地图中。
- Windows 应用发布、签名公证、安装器和自动更新分别验证。

## Capabilities

### New Capabilities

- `desktop-workspace`: 离线启动、中文输入、可调整窗口、准确的未配置状态和独立开发诊断入口。
- `core-contracts`: 类型化身份、独立版本、请求与执行计划、Job/Attempt、资产来源与制作记录的可校验数据契约。
- `worker-protocol`: 诊断进程的握手、探针、消息边界、协议错误及受管理退出。
- `platform-foundation`: 平台目录、进程启动与清理边界，以及可重复的核心/协议跨平台构建验证。

### Modified Capabilities

无。当前主规格目录尚无业务规格；本 change 全部使用新增 delta，审批并实现验收后再归档进入主规格。

## Impact

- 当前阶段仅修改本 change 文档和项目 OpenSpec 上下文；实际任务状态沿用 Beads 的规格编写 issue，不创建已获批准的实现任务。
- 批准后的实现预计新增最小 Rust workspace、桌面壳、核心契约、协议库、诊断 worker 和本地验证说明；模块先行，不创建研究报告中每个未来目录。
- 候选依赖限定为 egui/eframe、异步进程与消息所需的 Tokio、Serde 和基础平台目录/中文字体资源；仅在实现需要时引入，并锁定版本及记录许可。
- 本阶段不修改现有研究报告，不引入外部服务或遥测，不提交、推送或远程同步 Git/Beads。
