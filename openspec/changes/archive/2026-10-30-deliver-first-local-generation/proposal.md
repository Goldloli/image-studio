## Why

现有 Tauri 2 + React 工作区已完成界面验收，但仍只有示例、会话草稿和通信诊断，没有真实图片推理。用户在首批选型后要求继续；本提案以首位的 Z-Image Turbo 打通一个可安装、可生成、可取消、结果可找回的本地闭环。

**批准状态：用户已确认；实现与验收完成，2026-10-30 已归档。** 用户在完整提案展示后以“继续”确认实施及后续模型/隔离运行时下载验收。提案阶段仅查询元数据与源码；实现及实机证据按 tasks 逐项记录，不以批准代替验收。

## What Changes

- 首个型号固定为 Tongyi-MAI/Z-Image-Turbo，revision f332072aa78be7aecdf3ee76d5c247082da564a6；首条路线为 MFLUX 0.24.0 / MLX，隔离 Python 3.13 运行时，由 Rust 管理。
- 模型中心提供该型号的明确安装操作，显示下载体积、空间需求和真实状态；安装包含运行时、完整模型组件、校验和探针，支持中断后继续，不依赖用户系统 Python。
- 创作页提交单张文生图任务；支持 1024×1024、1024×768、768×1024，固定 q4 加载、9 步、单个活动任务，提供真实阶段、取消和错误。超出当前型号能力的字段不静默降级。
- 原始请求、有效计划和各次 Attempt 分开记录。生成进程返回的文件仅为候选，Rust 验证后原子登记图片、运行记录和成功状态。
- 引入一个默认项目、SQLite 元数据与不可变图片文件；保存草稿和任务，重启恢复已保存内容，未完成执行标记为中断，支持显式重试及 PNG 导出。
- 保留 Cherry 风格和现有离线示例；普通启动不下载模型、不自动加载推理，也不运行诊断。诊断 v1 保持原样，真实生成使用独立协议标识。

**提案阶段的下载量提示：** 当时只查询 HF 文件元数据，选中的原始组件合计 32,848,304,893 字节，约 32.85 GB / 30.59 GiB，另需 Python/依赖和安装临时空间。q4 是加载时量化，不能把原始下载量按 4-bit 推算。来源见 [元数据证据](references/z-image-source-metadata.json)，该提案来源文件不是可执行下载 manifest；正式安装清单与实机记录见 resources/local-generation 和 verification/first-generation-results.md。

本阶段以当前 Apple M3 Max / 128 GiB / macOS 验证，不承诺其他 Mac 配置或 Windows 推理。FLUX.2 Klein、BiRefNet、Real-ESRGAN 留后续 change；本轮不含图片编辑、多参考、批量队列、LoRA、图层蒙版、远程执行、模型卸载管理或公开签名分发。

## Capabilities

### New Capabilities

- model-installation：受控安装固定运行时与模型快照，校验、恢复、探针和真实就绪状态。
- generation-worker-protocol：与诊断隔离的生成握手、执行归属、有界进度、候选输出和受管理退出。
- local-generation：单模型有效计划、提交幂等、单活动执行、取消竞争、终态和重试。
- project-storage：默认项目与草稿持久化、不可变资产提交、崩溃恢复和原生 PNG 导出。

### Modified Capabilities

- desktop-workspace：从仅演示输入升级为真实就绪/生成/取消状态，新增已保存草稿恢复，保留中文输入与诊断隔离。
- workspace-canvas：保留离线示例及其身份，支持已有项目恢复；示例模板可更新已保存草稿但不产生生成资产或执行记录。

现有 core-contracts 和诊断 worker-protocol v1 不自动升级 schema，也不改写其诊断含义。

## Impact

Rust 核心增加执行与存储端口，桌面宿主接入 SQLite、下载器、受限 IPC 与原生保存对话框；新增受管理 MFLUX worker 和轻量原生进程监督入口。前端复用当前页面，接通模型、任务、结果和保存状态。

新增依赖和完整 macOS arm64/Python 3.13 安装锁在实现准备任务中固定，未形成精确文件与 SHA-256 清单前不能执行安装。提交结果、取消和恢复用真实持久化状态，不沿用诊断成功或示例图片充当验收。

完成条件是：干净隔离数据根中明确安装 → 中英文提示词生成真实图片 → 修改后再生成 → 取消一次执行 → 重启仍可查看草稿/结果 → 导出 PNG；同时通过安装中断、输出损坏、取消竞争和崩溃窗口检查。确认后才开始实现，全部验收后再归档。
