# Spec Delta

## Purpose

让已安装的 Image Studio 只从官方稳定版 Release 发现、验证和获取更新，并用清晰可恢复的状态完成平台允许的安装动作，同时保持本地数据和未签名 macOS 应用的安全边界。

## ADDED Requirements

### Requirement: 只发现官方稳定发布

更新检查 SHALL 只读取 `Goldloli/image-studio` 的公开 GitHub Releases，按语义版本比较当前应用版本。只有非 draft、非 prerelease 且版本号高于当前版本的 Release 才可作为更新；标签无法解析、版本相同或更旧时 MUST 不报告可用更新。

#### Scenario: 发现较新的稳定版
- **WHEN** GitHub Releases 中存在比当前应用版本更高的非 draft、非 prerelease Release
- **THEN** 更新状态返回该版本、发布时间、纯文本说明、对应平台安装包名称和大小

#### Scenario: 忽略草稿与预发布
- **WHEN** 最新 GitHub Release 是 draft 或 prerelease
- **THEN** 更新检查跳过它，只选择其中最高的稳定版；没有稳定版时明确显示无可用发布

#### Scenario: 网络或 API 失败
- **WHEN** GitHub API、网络或响应解析失败
- **THEN** 返回可读错误和发布页入口，不改变当前应用、模型或本地数据

### Requirement: 自动检查遵守用户偏好与时间窗口

桌面应用 SHALL 在核心界面就绪后延迟约 10 秒检查一次更新，自动检查最多每 24 小时执行一次；手动检查不受该窗口限制。自动检查开启时不得阻塞主工作区，失败 MUST 静默记录为最近检查失败，不弹模态框。发现新版本且通知开启时，SHALL 在当前会话显示一次非阻断通知并在设置入口显示角标；同一版本不得重复提示。

#### Scenario: 首次启动自动检查
- **WHEN** 自动检查开启，距上次自动检查已超过 24 小时
- **THEN** 应用在核心就绪约 10 秒后后台检查更新，不下载安装包且不阻塞创作

#### Scenario: 24 小时内重复启动
- **WHEN** 应用在自动检查成功或失败后的 24 小时内再次启动
- **THEN** 不再次自动请求 GitHub，手动检查按钮仍可用

#### Scenario: 发现新版本并通知
- **WHEN** 自动检查发现新版本且通知开启
- **THEN** 当前界面显示一次“发现新版本”的非阻断提示，设置入口出现角标，同一版本在本次会话不重复提示

### Requirement: 下载、校验与取消状态真实

更新 SHALL 只下载当前平台、操作系统架构和版本匹配的官方安装包，并从对应 `SHA256SUMS-*.txt` 读取精确 SHA-256。下载 MUST 使用临时 `.part` 文件、限制大小、拒绝符号链接或路径逃逸，并在接受字节后校验文件名与摘要；不匹配时删除临时文件且不得提供安装动作。进度 SHALL 显示已下载字节、总字节、速度和预计剩余时间，未知总量不得伪造百分比。

#### Scenario: 下载经过校验的安装包
- **WHEN** 用户确认下载一个可用稳定版
- **THEN** 安装包从官方 GitHub 资产下载到受管更新缓存，SHA-256 与对应 checksum 文件一致后才进入可安装状态

#### Scenario: 摘要不匹配
- **WHEN** 下载完成的字节数或 SHA-256 与 Release 资产和 checksum 不一致
- **THEN** 删除未验证文件，显示校验失败和重试入口，不提供打开或安装动作

#### Scenario: 用户取消下载
- **WHEN** 用户在下载或校验过程中取消
- **THEN** 下载在限定时间内停止、半成品被清理，状态回到可重新下载，不报告完成

### Requirement: 平台安装遵守未签名产品边界

Windows x64 SHALL 在已完成校验且没有生成、模型安装或清理进行时提供“安装并重启”；应用 MUST 先保存设置与未发送草稿并正常退出，再运行固定 NSIS 安装器，安装完成后以新版本重启。macOS arm64 SHALL 只打开已完成校验的 DMG，由用户拖入“应用程序”；应用 MUST NOT 自动替换运行中的未签名应用。两平台均不得绕过 SmartScreen、Gatekeeper 或系统权限提示。

#### Scenario: Windows 安装更新
- **WHEN** Windows 用户选择安装已校验的 NSIS 更新且当前无活动任务
- **THEN** 应用保存必要本地状态后退出，安装器运行并在完成后启动新版本；用户数据、模型和作品保留

#### Scenario: 更新时仍有生成任务
- **WHEN** Windows 用户请求安装更新而生成、模型安装或清理仍在进行
- **THEN** 拒绝启动安装器并说明需等待或取消当前任务，已下载更新保持可用

#### Scenario: macOS 打开安装包
- **WHEN** macOS 用户下载并校验更新 DMG
- **THEN** 应用打开该 DMG 和系统安装入口，明确说明需要手动拖入“应用程序”；不声称已自动完成安装

### Requirement: 更新中心状态可恢复且可操作

更新分类 SHALL 用单一状态流呈现未检查、检查中、已是最新、可下载、下载中、校验中、可安装、失败和取消。页面 SHALL 显示当前版本、最近检查时间、可用版本与发布说明，并提供检查、查看发布页、下载、取消、重试、打开安装包和显示文件位置等与当前状态匹配的受控动作。

#### Scenario: 首次打开更新分类
- **WHEN** 用户尚未检查更新
- **THEN** 页面显示当前版本、自动检查与通知开关、检查按钮和发布页入口，不显示虚假下载进度或安装按钮

#### Scenario: 已有更新下载
- **WHEN** 用户重新打开设置且更新下载仍在进行
- **THEN** 更新分类恢复真实字节、速度、ETA 和取消动作，不重新计算或重启下载

#### Scenario: 已下载但安装失败
- **WHEN** 打开安装包或启动安装器失败
- **THEN** 保留已校验文件并显示错误、重试、打开文件和发布会话入口，不把失败写成已更新
