# Proposal: redesign-settings-center

## Why

当前设置页虽然有五个职责分组，但视觉上仍接近一张扁平表单：左侧分类、标题和卡片之间缺少层级，控件尺寸与分组方式也不足以承载模型、运行时和存储的信息密度。用户希望参考 bilidown 的独立偏好设置形式，并借用 ASRbox 对本地事实与状态的分组表达，让设置页从“配置列表”升级为可快速扫描、逐组调整的偏好中心。自动更新不能再作为范围外事项：需要参考两个项目已有的更新检查、下载进度、校验、通知和安装边界，做成 Image Studio 自己的更新流程。

## What Changes

- 保留 Image Studio 的单主窗口结构，把现有设置页重构为 bilidown 式双面板偏好中心：深色/浅色中性背景上并列圆角分类栏与内容面板，分类使用图标、文字和强调色选中态。
- 设置内容改为“页面标题 + 状态 + 分区 + 行式控件”：每个分区是一张有边界的卡片，行内左侧说明配置，右侧放置分段控件、开关、选择器或数值输入；避免为每个字段重复外框。
- 统一六类设置的视觉语言：通用与外观、创作默认值、存储、运行环境、更新、关于；在不新增无关功能的前提下，补充摘要卡、状态徽标、路径行和运行环境分组。
- 新增第六类“更新”，承载当前版本、检查状态、自动检查与通知偏好、发布说明、下载进度、取消、校验、打开安装包和平台对应安装动作。
- 通用与外观增加可持久化的强调色预设与自定义颜色，默认沿用 Image Studio 橙色，预设不包含绿色；主题、字号、密度、减弱动效和侧栏状态继续保留。
- 存储页改为空间摘要加位置列表：优先显示总占用和可用空间，再逐项显示数据、模型、运行时、缓存、图片和日志路径，保留受控定位动作。
- 运行环境按“平台与设备、运行时就绪、各模型运行组合”分组；关于页使用品牌摘要、能力与来源证据分区，许可入口继续可展开。
- 自动更新只检查公开 GitHub 稳定版 Release；自动检查在应用核心就绪后延迟执行且最多每 24 小时一次，不自动下载或自动安装。Windows 可在下载校验后一键退出、安装并重启；macOS 因产物未签名、未公证，只打开经过校验的 DMG，由用户完成拖入“应用程序”。
- 保留现有即时保存/显式保存语义、错误恢复、未保存默认值切换确认和最小必要说明；移除重复标题、普通成功小字与无作用控件。

## Capabilities

### New Capabilities

- `application-updates`：定义公开稳定版发现、自动检查节奏、通知、安装包校验、下载状态、平台安装边界与失败恢复。

### Modified Capabilities

- `application-settings`：设置分组扩展为六类，并增加自动更新偏好、分区卡片布局、状态呈现和窄窗行为。
- `ci-release`：公开稳定版 Release 成为更新检查的正式来源，产物命名、校验和文件与发布说明的可消费性成为更新链路契约。

## Impact

- 前端主要涉及 `SettingsPage.tsx`、设置页样式、`settings-types.ts` 以及 `App.tsx` 的强调色应用。
- 桌面偏好文件需要兼容新增强调色与更新偏好字段，并保持旧偏好文件可逐字段回退、错误不覆盖和原子保存语义。
- 桌面宿主新增受控 GitHub Release 检查、安装包下载与 SHA-256 校验、进度事件、取消与平台安装入口；不得向更新流程开放任意 URL 或任意路径执行能力。
- 不新增独立设置窗口；设置仍从主窗口左侧导航进入，返回创作后保留原有工作区状态。
- 复用现有 GitHub Release 的 NSIS 安装包、macOS DMG 与 `SHA256SUMS-*.txt`，不新增云端服务；首版不提供 prerelease/beta 自动更新通道。提案阶段只提交文档，确认前不修改实现代码。
