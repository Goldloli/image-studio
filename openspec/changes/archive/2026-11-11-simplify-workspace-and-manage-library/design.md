# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本设计依据本地提交 `5c3c0e8` 的源码和正式规格，不代表新行为已经实现或验收。

- `App.tsx` 同时维护 `page`、`tabs`，挂载 `FeatureLibrary`、`TaskLibrary` 和开发诊断抽屉；作品的“制作记录”当前通过 `onOpenTask` 跳入任务页。
- `Workspace.tsx` 的会话行只有重命名按钮，底部有“示例灵感”快捷入口；空会话中央另有三张示例卡。
- `AssetLibrary.tsx` 已有网格/列表、组合筛选、稳定分页和原生导出，尚无作品收藏或删除状态。
- `PromptLibrary.tsx` 有独立 `prompt-license-disclosure` 区域，详情还有通用 `prompt-rights-note`；逐案例署名/链接属于另一个信息区域。
- SQLite 当前 schema 为 v5，作品为 `assets` 中的 primary；一次去背景另有同 Attempt 的 mask。草稿/Turn、Job、Attempt、资产和 manifest 通过稳定身份关联，不能硬删除会话行后破坏这些关系。

## Goals / Non-Goals

**设计目标**：复用当前 React、受限宿主命令、`StudioService` 和库模块的边界；通过少量附加用户状态支持可恢复删除，保持原执行事实和其他会话不变。用户已确认“删除会话保留作品、删除作品清理应用内原图”。

**本次不扩展**：回收站、撤销删除、批量删除/收藏、收藏排序或分组、磁盘全量清理、删除模型/运行时、目录迁移、跨设备同步、生成并行度以及重新设计灵感库。保留创作中央示例卡、案例来源链接及必要使用条件。删除产物不递归删除派生作品、导入文件、其他运行的输入快照或日志；本次清理对象是登记的本作品产物及专用展示缓存。

## Decisions

### 1. 保留单页导航和系统窗口边界

保留 `page` 导航与各保留页面的上下文，移除 `tabs`、`closeTab` 及标签条渲染；左侧主入口为创作、灵感库、模型、作品，设置/关于/主题保留原位置。顶部仅保留系统窗口操作所需的最小布局和拖动区域，分别验证 macOS 交通灯与 Windows 标题栏。

删除功能页、任务页的路由、页面挂载及专用 UI 文件/样式；从 App 和作品组件清除相关导航回调。旧页面目标使用同一导航白名单安全回退，不创建兼容性空页。移除开发菜单、诊断抽屉及其前端状态/轮询、设置中的开启按钮和面板状态行，保留独立测试工具与宿主内部诊断实现。

会话底部只删除“示例灵感”按钮及专用分隔/高度，不改中央示例卡。灵感库只删除通用许可折叠区与详情通用说明段落；关于页现有许可入口补足对应链接与版本，案例来源区及使用条件不变。

选择删除旧渲染链而非用 CSS 隐藏，因为隐藏组件仍可能发起查询、持有面板状态或被旧回调重新打开。

### 2. 制作记录在会话或作品上下文展开

复用已有单 Job 制作信息读取与格式化能力，抽取会话卡和作品预览都可使用的轻量记录区域；它只接收稳定 Job/Attempt 身份，先显示可读摘要，再展开 manifest/日志。需要时读取单项，不继续挂载全局任务列表或进行其轮询。

保留会话卡中的停止、重试及单活动/清理规则。作品预览里的“制作记录”改为打开当前区域，关闭恢复原预览；会话已删除的作品仍可读取制作信息。原 TaskLibrary 的全局搜索、状态筛选和任务导航随页面移除，不另做替代任务中心。

### 3. 用户状态附加于库，不修改不可变执行文档

在 `adapters/library/schema.rs` 增加 v5 → v6 事务迁移，并接入现有旧版本顺序升级链：

| 数据 | 拟增加字段 | 默认与用途 |
| --- | --- | --- |
| conversations | `deleted_at` | 空值表示未删除；保留来源外键、稳定 ID 和必要标题。 |
| assets | `is_favorite` | 0/1，默认 0；收藏仅属于作品 primary。 |
| assets | `deletion_state` | `active / pending / failed / deleted`，默认 active。 |
| assets | `delete_requested_at`、`deleted_at`、`deletion_error` | 保存已确认操作及未完成清理；同 Attempt 的删除组共同推进。 |

字段枚举约束、外键检查和必要索引随迁移落地，不修改 `asset_json`、请求/计划 JSON、manifest、原创建时间、尺寸和散列。收藏不复用灵感库收藏文件，避免不同身份空间混淆。

不硬删 Conversation/Turn/Job/Attempt/Asset 元数据行。删除会话清除其待发送文字、所有能力的源图选择及 UI 缓存，但保留生成历史所需的最小来源关系；这些记录不再通过正常会话入口读取。作品物理删除后保留带删除状态的资产元数据，供历史区分主动删除与外部损坏。

### 4. 会话删除是带门禁的单次事务

流程为：行右侧删除 → 绑定 ConversationId 的确认 → 宿主重查目标/活动状态 → 同一事务标记删除、清空未发送内容、修正活动选择 → 前端消费返回状态。

- 按目标会话检查 Pending 接收、预检、运行、提交、取消、资源清理；不能只看已创建的 Job。删除不代替停止，另一个会话运行时仍可删除空闲会话。
- 删除当前项后，从完整未删除集合按既有 `activity_seq` 与稳定 ID 选择最近活动项，不局限于前端已加载页。最后一项删除时，同事务调用现有默认值解析规则创建一个空会话。
- 对已删除会话的重复删除返回既有结果；默认替代会话不得再次创建。所有选择、草稿保存、重命名、发送和案例应用入口都在持久边界验证 `deleted_at`。
- 前端关闭目标编辑/重命名状态，停止或废弃其待发保存和分页响应，清除相关一次性导航意图；删除失败不先移除目标。确认期间目标内容发生变化时重新核对并刷新确认，避免旧确认丢弃后来输入。
- 作品来源展示原标题与“会话已删除”。筛选仍可按该原 ID 找到保留作品，返回会话按钮不可用，不能通过“查看图片”复活会话。

确认文案示意：“删除会话‘名称’？会话记录及未发送内容将移除，已生成作品会保留在作品库。此操作不可撤销。”默认焦点放在取消，Escape 取消并返回原行。

备选的会话级联删除会丢失用户要求保留的作品；单纯前端隐藏则会在重启、旧保存或分页后复活，均不采用。

### 5. 收藏采用明确设值和完整数据集查询

卡片正文底部右侧固定放置收藏和删除图标，预览维持独立区域。网格与列表共享操作，不依赖悬停才能找到作品按钮；会话按钮使用 hover/focus-within，在不能悬停的设备提供可发现显示。操作不会冒泡触发预览。

收藏命令传 `assetId` 与目标布尔值，避免 toggle 重放造成反向切换。前端按单作品串行提交并以宿主确认状态为准，失败保留最近确认值及可读错误。刷新或旧查询不得覆盖更晚确认的状态。

收藏筛选为“全部作品 / 仅收藏”，在宿主 SQL 条件中加入，不在当前已加载数组中过滤；列表、总数共享条件。沿用 `(created_at, id)` 稳定排序，不因收藏修改作品时间。分组候选维持当前整体候选语义，但统一排除删除完成作品；来源会话分组附删除标识。仅收藏下取消收藏成功后重新查询当前条件并修正总数、分页和阅读锚点。

### 6. 原图删除使用持久意图与可重试清理

一件作品的删除范围由宿主依据 primary 的 Attempt 身份解析：该 primary、同 Attempt 的 mask（如有）、明确属于它们的展示缓存。前端只能传正式作品 ID；导入源图、任意路径和单独 mask 不能作为作品删除命令的目标。确认框说明原图及配套产物会移除、外部导出副本保留、不可撤销。

先在库和执行协调边界检查所有未删除会话的全部能力草稿源图，以及 Pending/活动请求的冻结源图。存在引用则拒绝，给出关联会话；删除已完成历史引用不级联删除其独立派生结果。参考图解除、发送快照建立与删除必须共享裁决边界，避免检查后新建引用。

不引入新 crate、后台清理服务或通用文件管理器。在现有宿主排他所有权及业务锁内检查/持久化，在现有阻塞工作路径执行有限登记文件的清理；读取、源图解析、导出也检查删除状态，并与删除串行裁决。协议层返回受限状态，不返回供前端拼接删除的路径。

| 阶段 | 持久状态与副作用 | 对用户的表达 |
| --- | --- | --- |
| 确认前及检查失败 | active，未删文件 | 原作品保持，取消无副作用。 |
| 删除意图事务提交 | 整组标为 pending，记录确认范围；文件操作尚可恢复 | 显示删除中，禁用原图读取、导出及新源图使用，不报成功。 |
| 按登记路径清理 | 逐个删除受控普通文件；不存在视为已清理 | 继续等待，未动其他源图、模型、运行目录或外部导出。 |
| 任一步文件清理失败 | 整组标为 failed 并记录原因 | 卡片显示“删除未完成”及“重试删除”，不冒充正常可用或消失。 |
| 清理全部完成 | 整组标为 deleted 并清除收藏，修正选择 | 从作品/收藏/分组计数中移除，原会话卡显示作品已删除。 |

pending/failed 在作品查询中保留为不可预览的管理条目，继续使用同一计数集合，便于用户重试；收藏在整组完成前保留最近确认值。重试沿用已确认的范围，不扩大清理对象。重启取得数据根所有权后，对未完成组做有界恢复，失败继续可见，不无限重试或恢复为 active。

删除前验证规范化管理路径、受控父目录和文件类型，拒绝逃逸链接及特殊文件；删除不跟随链接。Windows 如需移除只读标记，只限已经验证的登记产物，不改变整目录或其他文件权限。文件被打开导致失败时如实保留未完成状态。若文件实际已删但最终数据库提交失败，仍可根据持久意图重试完成，不报告图片重新可用。

相较“先删除数据库再删文件”，本方案不丢失失败后的清理目标；相较“先删文件再写任何状态”，它能区分用户意图与普通资源损坏。部分清理后无法恢复字节，因此不承诺失败时原图完整，也不提供回收站或撤销删除。

### 7. 最小命令与展示契约

以下是拟用名称，实施时在现有 `host.rs → StudioService → adapters/library` 方向落地：

| 命令/数据 | 输入或新增字段 | 约束 |
| --- | --- | --- |
| `conversation_delete` | ConversationId、确认时草稿版本 | 重查版本和活动状态；返回删除事实与当前活动会话，重复请求幂等。 |
| `asset_set_favorite` | primary AssetId、目标布尔值 | 只操作 active 作品；返回持久确认值。 |
| `asset_delete` | primary AssetId | 首次执行前已确认；解析固定整组范围，返回完成或未完成状态；重复执行不扩大范围。 |
| `AssetLibraryQuery` | `favoritesOnly`，缺省 false | 与已有条件组合，计数与分页走同一查询。 |
| 作品/资产视图 | 收藏、删除状态/错误、来源会话删除标识 | 所有读取入口一致，原 Job 成功与当前文件可用性分别表达。 |

命令缺少原生环境、身份非法、目标不属于默认项目、版本冲突或忙碌时明确拒绝。页面收到旧列表或旧 Asset URL 响应时按查询序号和已确认变更版本丢弃；清理中/删除完成后清空相关预览、选中项和一次性查看意图，不把缓存继续显示为可用原图。

## Risks / Trade-offs

- 删除涉及数据库和文件，无法用一个 SQLite 事务覆盖全部副作用 → 持久意图、显式未完成状态、逐文件幂等与重启恢复，验收注入每个提交边界的中断。
- 来源关联和草稿异步保存可能复活已删除目标 → 保留来源墓碑、所有入口加删除检查，并使旧前端请求失效。
- primary 与 mask 可能只清理一半，Windows 文件占用和只读属性尤其需要验证 → 按整组推进状态，失败可重试，不提前成功。
- 生成期间删除源图可能破坏当前或下一次输入 → 检查全部草稿及活动快照，与建立引用共享门禁；旧历史引用只保留事实，需要已删除源图的重试明确要求重新选择。
- 移除顶部标签或开发栏可能残留布局间距及死回调 → 删除渲染/导航链，两个目标窗口和平台分别验收，不仅检查元素被隐藏。
- 物理删除后不能通过代码回退恢复图片 → 升级回滚只覆盖迁移事务；已成功升级的库不交给不识别 v6 的旧程序直接打开。回退演练使用隔离测试库及其资源副本，不添加产品自动备份或撤销承诺。

## Migration Plan

1. 用户确认本 change 后，建立实施 Beads issue，使用隔离旧库副本验证 v5 → v6、旧版本升级链与失败回滚；已有模型和资源不改写。
2. 先完成持久状态、命令与数据读写测试，再接入删除/收藏 UI；导航移除可独立提交，但作品制作记录的新入口须在移除任务页时一起可用。
3. 按各阶段运行对应测试并小步本地提交，最终完成跨模块质量门及 macOS/Windows UI 与原图清理验收，记录平台和未覆盖项。
4. 验收通过后归档 change、更新九份正式规格；同步修正 `feature-catalog`、`task-center` 的 Purpose，使其描述保留的能力/记录职责而非已退役页面。此次提案阶段不修改这些正式文件。
