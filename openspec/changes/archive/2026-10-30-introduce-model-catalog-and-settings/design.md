## Context

当前 `ModelLibrary` 直接写死一个 `installId` 和一张 Z-Image Turbo 卡片，`StudioSnapshot.model` 也只表达单个型号；搜索框是静态文字，筛选计数取自同一单模型对象的三个布尔值。设置页把 `dark` 与分组选择保存在 React state，页面文案明确写着“主题选择保留于本次会话”；关于页依赖同一快照中的单模型状态。

Rust 侧已有固定模型清单、安装锁、`ReadyRecord`、运行时探针与真实安装状态。`introduce-generation-conversation` 已完成实现与实机验收并归档，Conversation/Turn、每会话草稿和统一发送链路现为正式主规格。本 change 必须复用该事实，不能建立第二套会话默认值。

## Goals / Non-Goals

**Goals:**

- 把“目录里有哪些计划/已接入型号”和“这台机器当前能否执行”建成一个可测试的宿主投影，前端不再自行拼接模型状态。
- 让模型页查询、筛选项、统计、详情和现有安装动作都使用同一份登记事实。
- 为界面偏好与新会话创作默认值建立独立、版本化、可恢复的应用级持久化边界。
- 在会话 change 归档后，用它已经确定的独立新会话快照作为基础，以明确 delta 增加持久默认值和统一解析入口。

**Non-Goals:**

- 不在 React 本地存储中建立第二份模型或安装状态。
- 不引入模型热池、权重删除、目录迁移、更新策略或远程服务配置。
- 不把 `doc/08-first-model-batch.md` 或候选 JSON 直接当成可执行安装 manifest。
- 不自动执行设备探针、下载或推理来填充模型页。

## Decisions

### 1. 模型页读取一个宿主侧目录投影

新增只读 `model_catalog` 业务查询，输出限定字段的 `CatalogEntry[]` 和与完整目录一致的统计。每条记录分离：

- 产品登记：精确模型身份、家族、能力、计划/接入状态、详情与来源；
- 安装/运行事实：组件、运行时、设备探针和当前就绪原因；
- 验证事实：目标设备和实机证据范围；
- 可用动作：安装、继续、停止、用于会话及受限文档链接。

目录来源使用宿主内受控、版本化的产品登记；Z-Image Turbo 的安装详情链接现有 manifest 和 `ReadyRecord`，其余三个首批目标只登记“计划中”的产品信息。`doc/first-model-batch.json` 继续作为研究资料，不改造成下载清单。相比让 React 读取多个静态文件并自行推导，单一宿主投影能保证模型菜单、功能页和模型页共享同一状态。

查询不得扫描全部模型文件或执行散列。文件就绪与运行时状态复用现有持久事实；用户主动安装/探针才更新它。筛选在前端对有界目录内组合，ID 和计数来自投影，后续目录扩大仍可替换为宿主查询而不改变页面语义。

### 2. 模型状态使用分层状态而非状态机枚举

列表保留多个正交字段：`productStatus`、`componentsReady`、`runtimeReady`、`deviceVerified`、`executable`、`installPhase`。不能把“下载完成”映射为整体 `ready`，也不能让计划中记录拥有安装动作。

安装总览和行内状态由一个 `InstallStatus` 投影驱动。现有安装器继续是唯一写入者；模型页只发起已登记 `installId` 的安装、继续或停止命令。未支持 pause 时不伪造暂停。操作后的响应只用于关联进度，最终状态仍以宿主查询为准。

备选方案是扩展当前 `ModelView` 单对象为四张固定卡；这会把计划信息和设备事实混入固定 UI，目录一变化就要改 JSX，因此不采用。

### 3. 应用偏好与项目业务库分开持久化

主题、密度、字号、减弱动效、侧栏和新会话默认值属于应用级偏好，保存到平台数据目录下的版本化偏好记录，并由 Rust 原子写入。该记录应在主项目库不可用时仍能加载外观；模型身份仍只引用模型目录中的稳定 ID，不复制来源或路径。

每次写入使用字段级 schema 校验和单一版本号；读取时逐字段归一化。未知主题或越界字号只回退对应字段，不能重建整套偏好。保存失败时当前内存状态可继续供本会话使用，但 UI 必须说明尚未持久化。

备选方案包括 WebView `localStorage` 和现有 Library SQLite。前者引入不可控的 WebView 生命周期与清理；后者会让纯外观依赖项目库可用性并扩大业务迁移。两者均不采用。

### 4. 即时偏好与显式默认值采用不同提交语义

通用外观项在用户确认更改后立即写入并显示保存状态；创作默认值使用草稿表单，保存按钮提交整组已验证值。分组切换若有未保存默认值，必须让用户选择保存、放弃或取消。恢复默认只将当前组转为内置默认并走同一提交路径。

主题可在写入完成前先应用到界面以保持响应，但失败时不能显示“已保存”；重启只读取已提交值。设置默认值不能直接修改任何已有 Conversation Draft 或运行计划。

### 5. 新会话默认值只有一个解析入口

会话 change 归档后，由宿主 `resolve_new_conversation_defaults(explicit_override?)` 按以下顺序返回快照：

1. 创建入口显式覆盖的有效字段；
2. 已保存且字段有效的用户默认值；
3. 内置默认值。

模型目录负责判断 ID 是否登记及是否已安装；默认值解析保留用户选择的不可执行型号和阻塞原因，不静默替换。新会话创建时冻结返回结果；之后设置变化只影响以后新建会话。该函数是模型页、设置页和会话创建共用的唯一优先级入口。

常规“新建会话”按钮不携带覆盖值，始终读取用户保存默认值和内置回退，不复制当前会话的瞬时设置。显式覆盖只由同时让用户看见该选择的创建入口或受限深链传入；现有“用于当前会话”动作修改指定会话草稿，MUST NOT 被解释成创建覆盖，也不得静默创建新会话。无效覆盖应拒绝创建并返回原因，不能退回另一型号。

默认值表单按整组验证与提交：未登记模型、当前产品不接受的数量、画幅或种子必须阻止保存，并保留表单和上一份持久默认。已登记但暂未安装的模型可以保存，因为其阻塞状态可能由安装解决；从目录彻底移除或未来无法识别的模型 ID 不能继续作为有效默认，解析时回退该字段并明确提示。部分字段损坏只回退对应字段，不能覆盖其他有效字段。

会话能力已经归档，主规格要求新会话使用应用默认快照且不复制当前会话；本 change 只把尚无设置页时的内置回退扩展为持久默认与显式覆盖。前置依赖已满足，但本 change 仍须用户确认；开始实现前应重新读取归档后的 `conversation-management` 主规格并复核本 delta。若两者不匹配，应先修正文档。

### 6. 存储与诊断仅做受控只读投影

新增 `app_storage_summary` 查询，字段只含登记目录类别、宿主解析路径、可计算占用、可选空闲容量和错误。打开目录使用宿主白名单动作，WebView 不接收任意路径或 shell。

运行环境页读取真实平台、模型运行时和诊断状态；只有用户点击诊断才启动现有进程。迁移、删除和卸载分别需要引用检查、忙碌互斥、空间预算、原子切换与回滚；本 change 不暴露这些动作。

## Risks / Trade-offs

- [计划中型号被误计为产品能力] → 产品状态和可执行状态分开建模，统计使用不同字段；验收检查计划中条目不增加“正式接入”和“可执行”数量。
- [应用偏好与项目库生命周期不同] → 使用独立原子偏好文件；配置损坏按字段回退并保留可读错误，不把项目数据迁移绑进去。
- [两个 change 修改会话行为发生竞态] → 本 change 明确阻塞于会话 change 归档；开始前重新读取主规格并严格校验 delta。
- [模型页高频轮询干扰安装或筛选] → 查询只读且有界，过滤不发命令；安装状态轮询合并，迟到响应按查询代次丢弃。
- [路径或存储信息暴露过度] → 只返回白名单登记类别，打开动作由宿主解析；不向前端提供任意文件能力。
- [设备探针被误读为整模型性能认证] → UI 分别展示探针、整模型启动和目标设备实机证据，不以二极管状态代替。

## Migration Plan

1. 先完成并归档会话 change，确认 `conversation-management` 成为主规格后重新校验本 change。
2. 新建应用偏好记录及缺省生成逻辑；没有旧偏好记录时使用内置默认，不迁移项目业务数据。
3. 上线 `model_catalog` 只读查询，保留现有单模型安装命令和状态接口。
4. 将模型页与设置页切到新投影；模型菜单和功能页后续只依赖相同查询，不保留两套客户端清单。
5. 若 UI 需要回滚，可隐藏新页面入口并恢复旧单模型介绍视图；偏好记录和模型安装事实保持可读，不删除已经完成的安装。
