# Design

## Context

动机与范围见 [proposal.md](proposal.md)，可验证行为见 [specs/](specs/)。现状审计基于 2026-11-13 的桌面应用截图与源码：`App.tsx` 负责五个主页面的挂载，`Workspace.tsx`、`PromptLibrary.tsx`、`ModelLibrary.tsx`、`AssetLibrary.tsx`、`SettingsPage.tsx` 和 `ProductionRecord.tsx` 在多个层级重复同一标题、计数、来源、状态或技术身份。

本 change 只调整前端可见信息层级，不改变宿主事实、持久化身份或执行语义。必要的来源、许可、硬件门槛、错误和不可逆操作说明继续存在，但不再与普通辅助文案争夺首屏注意力。

## Goals / Non-Goals

**Goals**

- 为全站建立可检查的三级信息模型：首要任务、上下文状态、按需证据。
- 删除重复标题、装饰性眉标、通用副标题、逐条重复来源徽标和同义状态。
- 将技术身份、完整来源、许可、manifest 与日志收进明确的次级详情。
- 保持键盘、读屏、错误恢复和必要风险信息的可发现性。

**Non-Goals**

- 不改变任何宿主命令、数据库 schema、模型身份、请求契约或工作流动作。
- 不重做导航结构、页面布局、主题、图标体系或业务空态。
- 不删除来源、许可、模型验证边界、删除后果或失败恢复信息。
- 不新增通用文案组件或设计系统包；优先删除冗余内容，而不是继续抽象字符串。

## Decisions

### 1. 用三级信息模型决定内容位置

| 层级 | 内容 | 呈现规则 |
| --- | --- | --- |
| 首要 | 当前页面标题、核心内容、输入或主操作 | 每页一个主要标题；只保留驱动当前任务的信息 |
| 上下文 | 当前筛选数量、模型/资源状态、来源身份、保存进度 | 只在发生位置表达一次；状态变化优先于静态说明 |
| 证据 | 许可、精确版本、设备清单、AssetRef、Job、Attempt、hash、manifest、日志 | 使用现有披露、详情或高级区域；可复制、可键盘访问 |

替代方案是用 CSS 隐藏冗余文案，但这仍会占用可访问树、维护成本与后续误恢复风险；本次优先从渲染结构中移除，必要内容再重新归位。

### 2. 跨页面模板不新增抽象

删除共享的模板化副标题与 `library-kicker`/`section-label` 等装饰性文本节点。页面标题由现有导航和 `<h1>` 表达；必要提示继续使用页面自己的领域语言。若多个页面同时需要说明，优先在状态发生处写一句，不创建新的“说明组件”。

### 3. 主页面按任务层级精简

| 页面 | 删除或合并 | 保留或迁移 |
| --- | --- | --- |
| 创作 | `IMAGE STUDIO` 眉标、`本地图片创作` 副标题、图片常驻“查看大图”、输入区重复会话名/快捷键/保存成功 | 模型错误、预算警告、保存失败与重试；会话标题只保留页头一处 |
| 灵感库 | `PROMPT INSPIRATION`、页面通用导语中的重复工作流说明、顶部重复统计、逐卡“上游示例” | 页面级来源说明、当前筛选结果数、分类计数、案例使用条件与来源链接 |
| 模型 | 重复“模型”标题、静态“本地模型库”、通用副标题、顶部全量统计条、侧栏说明长文 | 侧栏筛选计数、真实状态、阻塞原因、主要动作；详情中的配方与证据 |
| 作品 | `正式 AssetRef · 跨会话`、卡片重复提示词、正常状态叠加“预览/可用” | 一次提示词与来源、必要状态、导出/删除/收藏；技术身份进高级详情 |
| 设置 | `应用配置` 标签、跨分组通用副标题、同义页面/区块标题、普通成功小字 | 当前分组标题、控件状态、失败/未知/不可逆限制、关于与许可入口 |

### 4. 卡片与详情共享事实但不重复摘要

灵感案例在页面级声明“上游示例、非本机生成”，详情不再重复同一徽标，仅保留来源、使用条件与模型不确定性。作品父级预览已有会话、型号、尺寸和种子时，制作记录首屏改为执行状态、错误或下一步；技术字段只在高级记录中出现。模型详情由“状态摘要 + 可展开证据”组成，保留全部事实但避免同义重复。

### 5. 删除辅助小字不改可访问语义

图标按钮、图片预览、筛选选中态和主题选择继续提供中文可访问名称、`aria-pressed`/`selected` 和其他现有状态属性。可以移除视觉辅助文字，但不能让动作只剩悬停提示。只影响视觉的装饰性文案删除后，读屏顺序应减少重复朗读；错误、警告和状态变化继续使用现有可访问角色。

### 6. 验收以重复内容断言和原生截图共同完成

组件测试在约定页面断言同义文案只出现一次，并覆盖空态、正常态、阻塞/失败态与详情展开。原生验收复用五个主页面与设置五组页，对照审计截图检查标题数量、首屏层级、必要说明可访问性和 960×640、1280×800 布局。截图或 CLI 校验不能替代真实桌面交互回归。

## Risks / Trade-offs

- 过度精简可能让来源、许可或风险信息难以发现 → 每个必要事实保留一个明确入口，并把它放在相关操作或详情上下文，不依赖全局底注。
- 作品或制作记录摘要可能被删除两次 → 用父级是否存在上下文决定是否显示摘要，而不是无条件删除。
- 图标或图片去掉文字后可能变成“猜谜” → 保留可访问名称、键盘焦点与必要的视觉提示；不能用悬停作为唯一解释。
- 列表计数只留一处可能让筛选状态不明显 → 保留当前选中筛选、结果数和清除动作，只删除重复的全量统计。
- 截图验收可能只覆盖当前数据 → 增加组件级静态文案断言，并覆盖空态、错误态和展开详情。
