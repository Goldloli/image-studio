# 三个计划模型的测试与验收计划

状态：**已批准；所有新增模型执行项当前为not_run**。本文件定义正式验收方式；尚未执行的新项目不得记录为通过。承接现有`model-validation`报告语义；新报告置于`verification/planned-models-<run-id>/`，不得覆写Z-Image历史认证。

## 1. 配置与门槛

| 配置键 | 型号与能力 | 必须分别运行的真实证据 |
|---|---|---|
| K-T | Klein distilled 4B，文生图 | 同q4/4步基线、安装、生成、离线、取消/恢复、原生使用 |
| K-E | 同一权重，单图编辑 | 独立编辑基线/源图、真实编辑及生命周期、原生使用 |
| B-R | BiRefNet epoch_244，CPU去背景 | 实际ONNX图合同、RGBA+mask、质量、生命周期、原生使用 |
| R-U | x4plus ncnn，tile128固定4× | 原生程序/模型身份、分块GPU执行、质量/接缝、生命周期、原生使用 |

安装证据可在K-T/K-E间引用同一精确快照/运行时的同一收据；不能引用其中一种能力的执行/取消/质量记录给另一种能力。每个报告绑定应用commit/二进制、worker包与源码、模型manifest、runtime锁、recipe/预处理、设备/OS及输入摘要。构建变化后的受影响项重跑，不能跨配置拼接出“全部通过”。

以下所有表格项目均为必需P0；适用配置列在开跑前确定，不能失败后改为可选。真实执行每种至少三次连续独立任务；每个记录自己的耗时、RSS、后端峰值（取得不到为null）、测量口径与输出，不用一次观测承诺其他Mac。没有设置未经实测的性能SLA。

## 4. 正式产品链路与生命周期

这些用例经正式宿主API/验收helper执行，走完整就绪校验、冻结、存储事务、监督及worker；直接调用上游API只能提供B组基线。fixture可用来稳定制造竞态，但不能替代标为真实模型的取消/恢复项。

| ID | 适用 | 操作 | 通过与证据 |
|---|---|---|---|
| P01 | 四配置 | 各用冻结输入经正式提交链路执行 | 正式PNG、Job/Attempt/AssetRef/RunManifest、实际能力/参数/输入hash一一对应；同配方与基线质量对照 |
| P02 | 四配置 | 安装完成后禁网运行整个宿主和后代 | 三型号全部实际本地运行，不下载或动态执行远程代码；独立网络限制证据 |
| P03 | 四配置 | 各连续三次独立任务，期间不重启应用 | 三次各自产物/来源正确，进程树回收且无跨任务串图；单次资源数据保存 |
| P04 | 四配置 | 真加载阶段接受取消，再显式重试 | 原Attempt取消且无正式输出，确认整树回收；新token/Attempt使用原源图/参数完成 |
| P05 | K-T/K-E/R-U | 真采样或多tile GPU计算中取消 | 有已进入实际计算证据，回收后才终结，取消不提交候选；ncnn后代也消失；显式重试成功 |

| P07 | 四配置 | 真实计算中强杀宿主，保留隔离根后重启 | 监督清理整树，租约未释前阻止新任务；旧执行Interrupted，无候选提升成功；同请求显式重试 |
| P08 | 四配置 | 双击/同键重发、跨型号忙碌、执行时换图/切会话 | 单Turn/Job/首Attempt，原快照不变；不同内容同幂等键拒绝；新请求不隐式排队 |

## 7. 报告和放行

每个结果保存schemaVersion、runId、caseId、configurationKey、required、status（passed/failed/not_run/blocked）、evidenceKind（metadata/source_review/fixture/device_probe/upstream_baseline/product_execution/native_daily）、原因和可定位证据。另存型号/能力/recipe、模型/runtime/worker/应用身份、设备、源图/指令摘要、Job/Attempt、输出角色/路径/hash及测量口径。报告必须逐项展开适用配置，不把表格一行当四配置均通过。

整批通过要求四配置所有适用P0、三型号安装、存储/迁移、原生质量审阅和Z-Image当前回归全部通过，且不存在缺必需证据的not_run/blocked。自动PNG检查与人工质量结论分别保存；某样图质量未通过不能仅靠结构合法标passed。对原模型未受影响的历史长矩阵可作参考，但本表明确指定的回归必须重跑。

三型号任一未通过就不能归档整批，也不能开始Qwen/MOSS实施。若用户希望缩小范围，需先修订并确认提案与deltas，不能临时把失败用例改非必需。后续Qwen/MOSS也须各自独立实测，不继承本批GPU、质量或性能结论。
