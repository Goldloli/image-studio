## Context

当前入口包括 Rust `apps/desktop/examples/generation-check.rs`、安装/存储/监督测试、Python worker 单元测试、前端状态测试以及 `scripts/check-generation-crash.py`、`scripts/check-offline-startup.py`。真实推理由 Rust 宿主 → 原生监督 → 私有 Python/MFLUX 执行，PNG 经正式资产事务提交。直接跑 MFLUX CLI 只能作为上游基线，不能证明产品装配。

2026-10-30 审查时前端 23、Rust 162、Python 8 项通过，Rust 有 2 项默认忽略；隔离安装和一张真实方图通过。上述数字是检查快照，后续执行应保存实际结果，不固定断言测试数量。默认目录未安装，以及运行时含绝对位置链接，是日常验收和隔离准备必须处理的约束。

## Goals / Non-Goals

目标：复用现有入口，用最少工具补齐用例编排、明确失败判定、证据索引和日常验收记录；为之后模型逐项加入同一测试语言建立基线。

边界：验收工具放在开发侧，不加入生产 IPC，不增加 GUI 测试控制台；不重构生成核心，不默认执行下载或故障；测试发现的行为缺陷按影响形成独立修复范围。OpenSpec tasks 是批准后的执行映射，持久进度仍在 Beads。

## Decisions

### 1. 三种执行层和一个统一报告

拟增加一个轻量 Python 编排入口 `scripts/check-model-usability.py`，复用现有 Cargo、npm、worker 与 acceptance helper，不引入测试服务或新运行时依赖。

| profile | 作用 | 模型/网络行为 |
|---|---|---|
| contracts | 自动契约、存储、协议、前端与受控故障 fixture | 不下载整模型，不做真实推理 |
| model | 明确隔离根上的安装/真实生成/真实取消恢复 | 显式安装模式才下载；否则只用现有完整安装 |
| daily | 检查并汇总原生人工/受控 UI 操作的证据记录 | 不自动操纵或重置默认用户库 |

验收入口为 `python3 scripts/check-model-usability.py --profile model --data-root ABSOLUTE_PATH --report-dir ABSOLUTE_PATH`；只有显式 `--install-mode network` 或 `cache` 才调用安装。调用者不得传模型下载 URL、任意 Python 或 shell 命令。若宿主系统走显式代理，调用外壳只设置代理环境变量，固定来源、组件身份和安装路径仍由应用清单控制。

`daily` 读取按用例填写的操作记录、截图、Job 与导出核验信息，对缺失项保持 not_run；不能用填写一个布尔值代替实际证据。采用现有原生 UI 操作能力或人工执行均可，记录操作方式。拒绝把浏览器端 Playwright 预览算成原生完成。

### 2. 报告和退出语义

JSON schema v1 包含：`run_id`、起止时间/时区、源码或输入清单摘要、二进制/worker 摘要、配置身份、profile、根路径类别、缓存/联网条件、用例集合版本、逐项结果、证据文件及摘要、分层汇总、人工质量结论和整体状态。

用例状态固定为 passed/failed/not_run/blocked；另用 `evidence_kind` 区分 contract_fixture/device_probe/real_execution/native_ui/historical_reference。历史参考只存在引用区，不进入当前 passed 分子。整体状态固定 passed/failed/incomplete，存在任何必需失败为 failed，否则存在必需 not_run/blocked 为 incomplete。

工具退出码建议：0 表示所请求 profile 的全部必需项通过，1 表示至少一个失败，2 表示缺少前提或必需证据，3 表示调用参数/报告格式错误。0 只表示该 profile，通过完整认证还须合并相同构建身份的三个 profile 并核对总门禁。实际 Task 终态必须读取 Job/Attempt 和正式资产，不能只信 helper 进程退出码；当前 generation-check 结束运行不等于该 Job 成功。

原始日志保留上限与失败尾部，报告内不嵌入巨量进度或 PNG。截图与文字记录不作为模型执行唯一证据，必须能定位正式 Job/Attempt/RunManifest。小型摘要和样图说明放 `verification/`；大模型、完整日志和本地输出放专用 `target/model-usability-<run_id>/`，报告明确清理后的可追溯限制。

### 3. 隔离、安装与默认目录

故障场景每组使用独立根。复用大模型可使用 APFS clone，但整个运行时位置不能直接迁移：使用固定、完整缓存交由正式安装器重建虚拟环境和 inventory；不修改链接/摘要伪造就绪。正式安装前记录空间预检与已存在资产清单。

默认目录通过不带 `--data-dir` 的真实 app 启动并在存储页/宿主路径中确认。测试前记录既有内容，新增验收会话用可辨识名称；结束后保留内容，由用户按正常方式管理。不用改写 HOME、替换系统目录、移动用户库或符号链接冒充默认路径。

首次冷安装必须从没有这些下载对象的缓存和未安装目标开始；不能删除用户缓存制造条件。默认目录空时可直接完成；已有安装时选新的隔离根冷安装，再独立做默认目录正常流程。外网不通时报告 blocked，不能改称缓存命中为冷安装。网络中断/Range/磁盘错误的可控覆盖优先用本地 fixture，真实冷安装记录实际网络过程与最终完整性。

### 4. 固定输入、质量与复跑

[test-plan.md](test-plan.md) 固定六个主要生成输入和种子，覆盖中英文、三个尺寸。重复运行验证身份、有效参数与输出有效性，不要求跨版本/GPU 逐像素相同。文本渲染与复杂布局是扩展质量观察，不把 Z-Image 的字体错误混为执行不可用，也不能将黑图、空白、严重损坏判为质量合格。

逐项保存审阅者、日期、样图、符合或不符合的具体提示词元素。单张结果可覆盖多个相关用例，但报告必须共享同一证据引用并注明复用；不得把一次运行伪装为多次连续运行。连续生成要求至少三次独立 Job、各自的 Attempt 与产物。

### 5. 生命周期、资源与性能

真实加载/采样取消和真实宿主 SIGKILL 使用隔离宿主的 live 子进程句柄，等待执行租约释放后确认回收；不使用全局 pkill 或恢复日志中的历史 PID。OOM、协议损坏、提交窗口和空间不足使用已标注的故障 fixture，不主动耗尽整机资源。

记录安装、执行前完整性校验、Job 接收到提交、模型加载与采样等可实际观测的分段。只有准确插桩才能给分段耗时；轮询只能记录阶段观测。当前每 Attempt 新进程重载，连续执行不能称为热模型池。报告操作系统文件/Metal 缓存可能复用；最大 RSS 与 MLX/Metal 峰值分列，缺测写 null，不能用 UI 宿主内存冒充 GPU 峰值。

### 6. 最小变化与备选方案

选择“现有 helper + 小型编排与证据契约”，因为关键安装和执行入口已存在。纯手写报告难以发现遗漏和错误终态；完整端到端平台或生产认证中心则超出当前需要。只有真实用例暴露缺口时才改 helper，补有意义的回归测试，不添加仅复述实现的测试。

## Risks / Trade-offs

- 真实下载与多次出图耗时较长 → 首次认证完成全部 P0，日后按模型/协议/存储/界面变化选择受影响用例；不可用选择性回归替代首次完整认证。
- 系统默认目录可能已有正在运行的宿主 → 等正常关闭或报告被占用，不强杀用户应用抢锁。
- 文档与当前代码可能继续变化 → 执行前固定构建及用例集合摘要；发现范围变化重新核对方案。
- 原生自动化能力不足 → 允许人工操作并保存具体证据，缺少证据时不绿色通过。

## Migration Plan

本 change 不迁移生产库或模型。先批准方案，再实现/完善验收工具和格式测试，执行隔离 contracts/model，再完成原生日常流程，最后生成并审阅证据包。故障修复如果改变已确认范围，先更新 proposal/spec/design/tasks。

认证通过后关闭 `image-studio-2px`；仅归档本 change 并新增 model-validation 主规格，不修改尚未批准的新模型 delta。工具回退只涉及开发入口和报告，既有用户内容不参与回退清理。
