# 现有模型测试与日常验收用例

这是批准后执行的用例定义，**全部尚未执行于本 change**。P0 为首次认证必需；P1 为扩展观察，可明确保留未运行而不阻塞本 change。真实安装/执行/原生 UI 与 fixture 的证据类别不可互换。

## 1. 前提与记录

固定当前应用构建、前端产物、监督二进制、内嵌 worker、模型 revision、runtime lock、OS/SoC/内存和用例版本。为隔离故障准备独立根；日常流程使用真实默认路径，预先记录原有内容且不清理。确认可用空间，以生产安装器的实际预算为准。

每项结果字段：case_id、优先级、profile、配置指纹、前提是否满足、操作时间、实际结果、状态、证据类别、证据路径/散列、Job/Attempt/asset（如适用）、失败/阻塞原因、人工审阅结论。以下“通过”均指本轮证据，不自动继承 2026-10-30 的历史结果。

## 4. 状态、取消、错误和恢复

| ID | 级别/层 | 操作 | 通过条件 |
|---|---|---|---|
| L01 | P0/model/native | 连续提交至少三个独立请求，每次等上一执行终结 | 三个独立 Job/Attempt/PNG，单活动约束成立，无旧图覆盖；至少一组在同一原生会话操作 |
| L02 | P0/model | 种子留空提交一次，在真实执行中取消该任务，回收后对同 Job 显式重试 | 首个 Attempt 已冻结实际 u32；重试保留该种子，不重新随机；可与 L04/L05 共用取消证据，成功任务再生成须另建 Job |
| L03 | P0/native/contracts | 原生快速重复点击发送及受控同幂等键重放 | 单意图只收一个 Job；同键不同请求拒绝；保留原输入与错误 |
| L04 | P0/model | 在真实 loading 阶段取消 | 先取消/清理，确认进程回收和租约释放后 Cancelled，无新正式资产 |
| L05 | P0/model/native | 在真实 sampling 阶段取消，再显式重试 | 旧 Cancelled、新 Attempt/token，旧进度不串入；重试成功并可查看原输入 |
| L06 | P0/model | 真实 sampling 至少一个 GPU 步返回后强杀本次隔离宿主，再启动同根并显式重试 | 旧 Attempt Interrupted；旧租约忙时禁止新执行；回收后新 Attempt 成功，旧记录保留 |
| L07 | P0/contracts | 取消/候选/失败竞态、旧 token、帧过大、错误握手、异常 PNG、提交崩溃窗口 | 每个 fixture 正确拒绝或终结，资产数/终态不虚增；无缺失场景被当作通过 |
| L08 | P0/model/contracts | 空/空白提示词、非法种子、未支持尺寸/数量、超 16 KiB、含模板超 512 token | 在对应边界明确拒绝，无静默截断/改配方；输入可恢复；真实 tokenizer 至少验证一例超限 |
| L09 | P0/contracts | 明确 OOM、普通异常、超时、通道断开 fixture | 仅真实识别的 OOM 分支显示内存不足，其余错误可区分；进程回收，不能创建成功资产 |
| L10 | P1/model | 同配置重复相同输入与种子 | 比较样图和有效参数；只记录是否字节一致，不把非逐像素一致自动判为失败 |

不得在默认用户库做 L06 或文件破坏。不能用故障 fixture 代替 L04/L05 的真实模型取消或 L06 的真实 GPU 执行；不能用强杀进程模拟其尚未发生的真实加载阶段。

## 5. 日常原生流程

以原生 app、实际默认目录为准；截图同时保存逻辑窗口尺寸和主题。1280×800 浅色、960×640 深色覆盖关键页面；其余组合做有界布局检查，无需重复下载和生成。

| ID | 级别 | 用户操作 | 通过条件和证据 |
|---|---|---|---|
| D01 | P0 | 正常启动，查看设置存储/运行环境和模型页 | 实际默认目录可核对，模型/环境/设备状态真实；未安装不会显示可执行 |
| D02 | P0 | 通过模型页明确安装或确认已有正式安装 | 安装过程、来源、体积/空间、各就绪条件正确；已有安装注明条件，不伪报冷安装 |
| D03 | P0 | 新建“日常验收”会话，输入/编辑中文，使用实际拼音输入法确认和多行粘贴 | 已确认文本准确，组合未确认文本不被误发；保存失败有反馈，不把浏览器模拟事件当原生 IME |
| D04 | P0 | 从模型页用于明确会话，发送中文提示词，再连续完成至少两轮 | 每轮占位、实际阶段、最终 PNG 原位显示；三个独立 Job，作品数与正式资产一致 |
| D05 | P0 | A 生成期间切到 B，编辑另一提示词，回 A 查看或停止 | A 继续且可发现；B 可编辑但不隐式排队；进度/结果不串会话，停止归属明确 |
| D06 | P0 | 从任务详情和作品返回来源会话，检查制作记录 | 模型、种子、尺寸、Attempt、错误/日志可核对，来源可靠，不按提示词猜会话 |
| D07 | P0 | 保存未发送草稿、当前选择、主题和新会话默认值后正常退出，再普通启动 | 各自按已有优先级恢复；默认值不改旧会话；历史 PNG 可解码显示 |
| D08 | P0 | 用系统保存面板导出至含中文/空格的新路径，再取消一次导出 | 导出散列一致、没有重复内部资产；取消不改变任务/作品数，不覆盖用户既有文件 |
| D09 | P0 | 在两个指定逻辑窗口、浅/深色检查模型/创作/作品/任务/设置及键盘操作 | 主操作、状态、错误可读，中文可访问名称和焦点可用；保存截图/操作记录 |
| D10 | P0 | 安装完整后禁网运行实际原生应用并完成一轮生成 | 原生显示正式结果；网络限制覆盖宿主与后代，不是只设 HF_OFFLINE 环境变量 |
| D11 | P1 | 重复日常会话与作品浏览，记录应用/执行资源 | 记录可观测的趋势和异常，不以未设基线的内存数字作硬性速度承诺 |

D04 与 L01 可以共用同一组三轮真实操作；D10 可覆盖一个 G 用例。其他 G 项允许隔离 CLI 执行，但不能把它们替代 D04。预览截图不能代替实际导出文件的散列核对。

## 6. 门禁和执行顺序

先固定构建 → contracts → 隔离安装/真实执行/恢复 → 默认目录日常流程 → 汇总与人工审阅。P0 均通过、必需证据完整、当前配置一致时才认证 passed；任一失败为 failed；存在未运行或环境阻塞为 incomplete。P1 的文字渲染观察只作为能力边界记录，严重黑图/文件损坏仍按其对应 P0 失败。

复跑策略：模型/运行时/worker 配方改变需全部 G 和 L04–L06、I02–I03；安装器改变需 I 全组；存储/监督改变需 L 生命周期与 D06–D08；界面改变需 D 对应场景。首次认证仍须所有 P0，不能只选回归子集。最后人工核对“报告结论”和真实资产/截图一致，并记录验收日期及审阅者。
