## ADDED Requirements

### Requirement: Windows 功能回归不执行模型推理

Windows 功能回归 SHALL 使用当前构建的 x64 安装包和 WebView2 原生应用，验证安装、升级、界面、会话、作品管理、导出、受控删除、设置及启动诊断。该验收 MUST NOT 下载或安装模型、准备私人运行时、启动推理 worker、创建生成任务、执行 GPU 计算或生成新的模型图片。

#### Scenario: 当前构建的纯功能回归

- **WHEN** 变更只影响界面、文档或本地管理，且验收采用 Windows 功能回归
- **THEN** 测试使用既有或隔离的测试数据完成安装与功能操作，不下载模型、不启动生成 worker，也不要求新的图片输出
- **AND** 界面截图、既有作品、日志和文件哈希可以作为证据，但报告明确标注这些不是本轮模型生成结果

#### Scenario: 无模型或网络时的功能可用性

- **WHEN** 应用数据根没有可执行模型或网络不可用
- **THEN** 应用仍可从安装包启动，并完成导航、草稿、既有作品查看/导出、设置与错误状态检查
- **AND** 模型页如实显示未安装/未就绪原因，不因功能验收而自动下载或安装组件

#### Scenario: Windows 文件占用和只读删除

- **WHEN** 测试资产处于只读状态或仍有未关闭的文件句柄
- **THEN** 删除失败显示可重试状态且不虚报成功；解除条件后可完成删除，其他用户文件、外部导出和作品历史保持

#### Scenario: 功能证据不得冒充生图认证

- **WHEN** 功能回归全部通过但未执行模型推理
- **THEN** 结论只声明安装、升级、原生 UI 与本地管理功能通过
- **AND** 不得声明当前构建完成七模型八能力、GPU 资源、图片质量、取消/强杀恢复或性能重认证

## MODIFIED Requirements

### Requirement: Windows 12 GB 标准档在当前主分支上有真机回归证据

Windows 验收 SHALL 在目标 Windows 10 x64 / RTX 3080 Ti 12 GiB 真机上记录当前构建提交、安装包或可执行文件哈希、设备身份和验收档位，并审查当前构建相对既有生图基线是否改变执行面。功能回归完成当前构建的安装、原生界面和本地管理验证，不执行模型推理。只有模型、运行时、worker、协议、计划/配方、设备门槛、安装量化或生成提交/恢复链发生变化，或既有基线缺失、不完整、不可追溯时，才 SHALL 执行完整生图认证：已安装的标准档能力至少各完成一次产品内真实生成、编辑、去背景或放大，记录 CUDA reserved、private commit、可用物理内存最低值、加载/生成墙钟和导出逐字节一致性。未发生执行面变化且基线完整时，功能回归 MAY 复用该目标机生图证据，但不得把它改记为当前构建的新实测。

#### Scenario: 仅界面和本地管理变化

- **WHEN** 当前构建相对完整生图基线没有执行面变化，且既有证据绑定目标机、模型/运行时身份和结果文件
- **THEN** 当前构建可以在完成 Windows 功能回归后声明功能验收通过
- **AND** 报告引用既有生图基线，不下载模型、不运行推理、不生成新图片，也不声称重新完成生图认证

#### Scenario: 执行面发生变化

- **WHEN** 当前构建改变模型、运行时、worker、协议、计划/配方、设备门槛、安装量化或生成提交/恢复行为
- **THEN** 必须执行目标机完整生图认证，覆盖受影响的标准档能力并记录原资源、时限、取消/恢复与导出口径
- **AND** 功能回归通过不能替代该认证，未执行项保持 `not_run`

#### Scenario: 基线缺失或差异无法分类

- **WHEN** 找不到完整目标机生图基线，或无法确定 diff 是否改变执行面
- **THEN** 默认要求完整生图认证，不以“可能不受影响”的推断关闭验证

#### Scenario: 证据身份与结论标签

- **WHEN** 验收报告同时引用当前功能回归和历史生图认证
- **THEN** 分别记录当前提交/安装包哈希与历史基线提交/证据路径，并分别标注“功能回归通过”和“生图基线复用”
- **AND** 不得把两类结果合并成“当前构建全部重新认证通过”

#### Scenario: 档位投影与设备身份

- **WHEN** 在完整生图认证要求生效的当前构建上打开模型页
- **THEN** 设备身份显示 RTX 3080 Ti / 约 12,288 MiB / sm86
- **AND** 已安装型号显示 `standard · 1024² · bfloat16`，不出现紧凑档投影
- **AND** Z-Image Turbo 按 12 GB 门槛显示为满足（若已安装则可执行）

#### Scenario: 标准档生成与资源口径

- **WHEN** 完整生图认证要求对已安装的标准档能力发起产品内真实执行
- **THEN** 记录输出 PNG 的尺寸、字节数与 SHA-256，以及 CUDA reserved、进程 commit、可用内存最低值和墙钟耗时
- **AND** 资源口径逐项对照标准档合同（CUDA reserved ≤10.5 GiB、private commit ≤24 GiB、可用物理内存最低 ≥2 GiB、加载 ≤600 s、生成 ≤900 s、无 WDDM 共享内存回退）

#### Scenario: 种子缓存重装与重启恢复

- **WHEN** 完整生图认证要求因激活身份变化拒绝旧就绪记录，随后使用已验证的本地种子缓存重装
- **THEN** 安装记录标注为种子缓存类型并完整记录阶段与耗时，不宣称验证了下载链路
- **AND** 重装后可完成一次标准档生成，导出文件与资产逐字节一致
- **AND** 重启应用后型号仍为就绪，旧作品可重开

#### Scenario: 安装期量化准备被内存预检阻止

- **WHEN** 完整生图认证需要安装量化准备，而本机可用物理内存低于 28 GiB 且 commit 余量低于 26 GiB
- **THEN** 安装器在开始量化前以包含实测值与可行建议的中文错误失败
- **AND** 不留下部分 prepared 缓存或安装记录，且该事件以 `blocked` 记录，不得改写为通过
