# Windows model-parity — independent pre-acceptance audit (2026-11-04)

Status: **audit report only — this file records no product pass/fail.** It is an
independent read-only review of the parity implementation at commit
`888dcca` (`docs(openspec): check the staged executor and ncnn worker tasks`)
performed before the installed-app acceptance run. Product code was not
modified; the only new file in this change is this README.

- Reviewer: `rust-identity` (also the author of the Windows identity/protocol
  foundation and the BiRefNet ONNX worker, reviewed here against the spec rather
  than against that authorship).
- Scope: identity consistency (design.md §11), security boundaries, install /
  lifecycle correctness, and the remaining evidence gaps measured against
  `tasks.md` and `test-plan.md`.
- Method: static reading of the cited sources, cross-checks with small
  read-only Python scripts (kept under git-ignored `target/`), and running the
  existing test suites listed in §1.3. No install, no generation, no GPU job,
  and no app launch was performed by this audit.
- Legend: **[V]** verified from files or by running a command; **[I]** inference
  or judgment not directly exercised here.

---

## 0. Executive summary

1. **Identity is consistent [V].** Every string frozen in `design.md` §11
   (model variant, capability, recipe, snapshot, runtime, worker build) matches
   the constants in `studio-core`, `worker-protocol`, all three Windows workers,
   the installer profiles' `execution_snapshot_id` mapping, the six model
   manifests, the two runtime manifests, and `model-catalog.json`. The
   "install id / model manifest id vs worker snapshot id" distinction is
   implemented explicitly (`installation.rs` `execution_snapshot_id`) and the
   probe, `ReadyRecord`, `ReadyPaths` and `ExecuteRequestV2` all use the
   snapshot identity. No mismatch was found.
2. **Security boundary is solid [V].** The MOSS pipeline is vendored in the
   worker with a frozen SHA-256 that is checked before import, the model
   directory ships no Python, no `trust_remote_code` exists anywhere, every
   worker forces HF/transformers offline, the installer URL allowlist and
   redirect policy are strict, archives are extracted member-by-member with
   hash checks and traversal/link rejection, and BiRefNet/Real-ESRGAN license
   texts are archived under `<data>/licenses/<install_id>/` and hash-verified.
3. **Install/lifecycle is carefully built but has three real gaps [V/I]:**
   the design-mandated **install-time RAM preflight before Qwen/MOSS prepare is
   missing** (§R2), the **prepared cache is not digest-bound or invalidated when
   the model snapshot changes** (§R3), and **embedded worker wheels are outside
   the runtime manifest identity**, which creates a future update/repair
   lifecycle deadlock (§R4). Host-side hardware gating is also only enforced at
   UI/model-selection boundaries, not in `install()`/`conversation_send()`
   (§R5).
4. **The dominant acceptance risk is missing evidence, not missing code [V].**
   `verification/windows-parity-app/ACCEPTANCE-PLAN.md` states plainly that no
   acceptance case has been executed; per-model empty-cache installs, native
   Real-ESRGAN install, UI runs, hard-kill and several cancel cases do not
   exist yet. Worker-level evidence is strong (7/7 real v2 protocol passes).
5. Must-fix list before acceptance: **§6.1 items M1–M4** (RAM preflight,
   prepared-cache integrity/invalidations, worker-wheel update path, then the
   acceptance run itself). The rest are low/informational or evidence tasks
   that the acceptance run naturally produces.

### 1.6 Lifecycle/security facts verified in code

- **Shared v2 runtime**: Windows rebuilds into a staging directory, installs all
  frozen wheels plus the two embedded worker wheels into `Lib/site-packages`,
  runs the worker probe, writes a runtime activation record, and only then
  renames staging into place (`installation.rs:1900-2073`, `1024-1031`,
  `984-1022`). Reuse requires the same runtime id + manifest digest and all
  recorded file metadata (`:994-1006`, `:1919-1944`).
- **Ready record**: binds runtime manifest digest, model manifest digest, worker
  probe identity and licenses (`:85-89`, `:858-878`, `:1326-1408`,
  `:1494-1557`); startup reports `ready` / `unavailable` / `interrupted` without
  activating a partial install (`:1398-1408`).
- **Prepared-cache layout**: `<data>/models/<model.id>.prepared`
  (`installation.rs:901-907`, `:2230-2245`; host
  `apps/desktop/src/adapters/generation.rs:925-931`; worker derives the same
  path from `model_path`:
  `tools/diffusers-worker-windows/studio_diffusers_worker/backends/common.py:55-64`,
  `backends/qwen.py:208`, `backends/moss.py:235`). The recorded path is checked
  on ready (`installation.rs:920-938`, `:1641-1646`).
- **Staged recipes** refuse to start if the prepared cache is missing
  (`generation.rs:350-366`), and the diffusion worker enforces the Gate-0
  budgets (`resources.py:194-221`) plus per-stage RAM checks
  (`backends/qwen.py:213,258,291`, `moss.py:240,296,329`, `klein.py:82`).
- **Native platform gate**: `kind:"native"` requires
  `platform == windows-amd64` on Windows and `macos-universal2` on macOS; native
  manifests must have `executable`, no interpreter and no wheels
  (`installation.rs:1282-1294`, `:1096-1103`).
- **Real-ESRGAN Windows fixes**: verbatim `\\?\` paths are stripped before
  calling ncnn (`tools/realesrgan-worker/src/main.rs:182-257`, `:516-527`); the
  official Windows ncnn build writes RGBA and the worker normalizes to 8-bit RGB
  while rejecting non-opaque alpha (`main.rs:616-700`, unit tests
  `:1078-1120`); exact 4× and RGB output contract is validated before emit
  (`:315-391`, `:616-634`).
- **Cancel / lease / kill**: supervisor acquires an execution lease and spawns
  the worker suspended in a Windows Job Object, resumes only after the Job
  assignment and lifecycle publication (`tools/inference-supervisor/src/windows.rs:41-77`);
  handshake/loading/generation deadlines (`:344-381`); cancel grace, Job
  termination and `CLEANUP_INCOMPLETE` lease retention (`:388-418`);
  candidates are published only after the worker tree is gone (`:421-449`).
  Timeouts default to load 600 s / generation 900 s
  (`src/lib.rs:195-215`); desktop overrides Qwen/MOSS to 1920 s generation and
  Klein to 900 s (`apps/desktop/src/adapters/generation.rs:367-390`) while the
  worker enforces the 900 s product budget itself (`resources.py:216-219`).
  Supervisor integration tests pass (§1.3).
- **Worker module allowlist**: `studio_mflux_worker[_v2|_v3]`,
  `studio_onnx_worker`, `realesrgan-native-worker`,
  `studio_diffusers_worker`, `studio_zimage_cuda_worker`
  (`apps/desktop/src/adapters/generation.rs:313-322`), plus build-identity
  pinning per Windows recipe (`:344-349`, `:932-943`).
- **Security**: MOSS pipeline 25,060 B / SHA-256
  `1dac1aca9feb1bfdfc727a401e4b67d61a505d3190706d1b7d2d784f88678b31`, verified
  before import, loaded from the package, never from the model directory
  (`studio_diffusers_worker/vendored/__init__.py:17-54`); the model manifest
  ships no `.py` files; no `trust_remote_code` anywhere in `tools/` or
  `apps/desktop/src` (grep); vendored file has no network/process/eval/exec
  primitives (only `from_pretrained(...).eval()` method calls). Offline env is
  forced by the worker (`studio_diffusers_worker/__main__.py:459-466`), the
  supervisor (`windows.rs:58-61`) and every installer subprocess
  (`installation.rs:2355-2357`). URL allowlist is strict (`:2988-3011`,
  redirects `:3017-3023`), manifests/archives are structurally validated
  (`:3136-3166`), extraction rejects links/special/duplicate/escaping members
  and verifies every member hash (`:2263-2335`), wheels are extracted with
  path/link/size limits (`:3330-3420`), and license records are verified on
  every ready check (`:961-983`, `:1661-1668`).

## 6. Must-fix / must-run before acceptance

### 6.1 Code/docs (ordered)

1. **M1 — RAM preflight for install-time prepare (R2).** Installer or
   `prepare_cache` must check available physical RAM (≥28 GiB) or commit
   headroom (≥26 GiB) before quantization, fail with an actionable message, and
   carry a unit test with injected facts. This is the only spec requirement in
   this audit that is unimplemented and explicitly expected by the acceptance
   plan.
2. **M2 — Prepared-cache integrity and invalidation (R3).** Persist the
   prepare-report inventory in the ready record and verify it on ready/startup;
   force a rebuild when the model-manifest digest changes (or delete the cache
   before re-install). This closes both tamper and model-update staleness.
3. **M3 — Worker-wheel update/repair path (R4).** Bind the embedded worker
   wheel digests into the runtime activation/ready identity (or bump the runtime
   id with worker builds), and test the "runtime reusable, wheel build changed"
   path so a future app update cannot deadlock installation.
4. **M4 — Host-side hardware gate at install/send (R5).** Add the
   `DeviceFacts` threshold check to `install()` and `conversation_send()` with
   the actionable reason (unit tests with injected facts).
5. **M5 — Documentation hygiene (R10/R16/R19/R21).** Refresh the stale
   Real-ESRGAN status, clarify the native `install_layout`, fix the
   prepared-cache comment, and record the worker-wheel-embedding deviation so
   the archive does not cite obsolete `worker_wheels_pending` wording.
6. **M6 — Process hygiene (R12/R9).** Restore/commit the dirty generated files,
   update `tasks.md` 2.2/3.2/3.4 checkboxes with evidence links, and run R2-1
   from a clean commit.

### 6.2 Acceptance run (produces the remaining evidence)

Run `verification/windows-parity-app/ACCEPTANCE-PLAN.md` in order from a
recorded clean build commit: preflight + manifest verification →
cache seed dry-run/real seed → per-model empty-cache installs (I2-1a–f,
including prepare with the RAM preflight and the Real-ESRGAN native probe) →
seeded installs (I2-2) → functional generations (P2-1/P2-2/P2-3/P2-4) →
cancel/kill/recovery (P2-5, add Klein edit, BiRefNet, MOSS, hard-kill) →
native UI/export/task/works (P2-6) → hardware/license display (P2-7) →
macOS regression + frontend checks on the Mac → 5.1 summary → archive (5.4).
